## 0. 이 문서를 읽는 법

§3 결정 표가 이 문서의 뼈대다. 각 절은 그 결정을 화면·서버·테스트로 풀어 쓴다. PR 은 §11 순서로 나뉘고,

## 1. 배경

warehouse-app 은 Windows 스테이션과 Android 핸드헬드 두 프로필을 갖는다. 7월 설계(`2026-07-20-warehouse-native-app-design.md` §3)는
프로필마다 화면군을 따로 두기로 했지만, 실제로는 **홈 타일 순서만 다르고 모든 작업 화면이 폰용 세로 1열 레이아웃을 공유**한다
(`src/profiles/station/StationHome.tsx` 와 `src/profiles/handheld/HandheldHome.tsx` 만 다르다. 기본 창 크기 800×600).

그 결과 스테이션은 관리자 웹 페이지처럼 보이고, 마우스를 거의 쓰지 않는 현장 작업에 맞지 않는다. 출고 한 박스를 예로 들면:

```
송장 스캔 → 화면 이동 → 「출고 준비」 클릭 → 위치 스캔/클릭 → 상품 스캔 … → 「출고완료」 → 「다음 송장 스캔」 클릭 → 대기 화면
```

- 박스마다 클릭 2회 이상
- 스캔 결과가 글자로만 나온다(소리·화면 피드백 0, 기능키 0)
- 송장 정보는 한 줄, 품목 진행은 「할당 N / 피킹 N / 남은 N개」 문장

국내 현장 프로그램(사방넷 풀필먼트·이지어드민 ezPos·플레이오토, 셀메이트 일부)과 ShipStation·ShipHero 를 조사한 결과,
공통 패턴은 다음과 같다: 포커스 고정 단일 입력 · 「송장 → 품목」 2단 상태기계 · 스캔 1회 = +1 과 줄 음영 · 성공/오류 소리 ·
인쇄된 명령 바코드 · 거대 강조 요소 하나 + 촘촘한 표 · 보류·취소는 스캔 순간에 차단 · 입고·이동·실사도
「위치 → 상품 → 수량 → 누적 → 일괄 확정」. F1~F12 단축키는 국내 제품 문서에서 확인되지 않았다(명령 바코드가 대체).

## 2. 목표와 성공 기준

1. 스테이션에서 출고 한 박스가 **마우스 0회**로 끝난다 — 송장 스캔 → 상품 스캔 → 자동 출고 완료 → 다음 송장
2. 송장 정보와 품목별 스캔 현황이 **한 화면**에 보인다
3. 스캔 결과를 **화면을 보지 않고도** 안다(성공·오류·완료 소리, 화면 테두리)
4. 모든 작업(출고 검수·배치·입고·적치·이동·실사·재고 조회)이 같은 셸·같은 조작 문법을 쓴다
5. 핸드헬드 프로필은 이번 작업으로 동작이 바뀌지 않는다
6. `npm run type-check` 에러 0 · `npx jest` 실패 0 · warehouse-app `vitest`·`tsc -b` 통과(§10 게이트 신설)

## 5. 스테이션 셸

### 5.1 레이아웃

위 탭 바(52px, 어두운 바탕) · 작업 영역 · 기능키 바(56px) · 상태바(28px). 창 기본 1280×800, 시작 시 최대화(`tauri.conf.json`).

### 5.2 작업 액션 레지스트리

화면은 액션을 **한 번** 선언한다: `{ id, key, label, command, enabled, run }`. 다음이 모두 이 선언에서 파생된다.

- 기능키 처리
- 기능키 바 렌더링(현재 `enabled` 인 것만, 권한 없는 것은 그리지 않는다 — U2)
- 명령 바코드 처리(§5.3)
- 명령 바코드 시트(§5.3)

탭 전환(F1~F6)은 셸 자신의 액션이다. 같은 키라도 화면 상태가 바뀌면 다른 액션일 수 있다(레지스트리는 상태별로 선언된다).

### 5.3 명령 바코드

- 스캔 버스(`ScanProvider`) 앞단에서 명령 접두어를 가로채 현재 레지스트리로 보낸다. 일반 구독자는 명령을 받지 않는다
- 모르는 명령·현재 꺼진 명령은 오류음
- **코드는 숫자와 기호만**(예: `%90%08`). 스캔 버퍼는 한글 IME 조합 입력(`isComposing`)을 버리므로 영문 명령은 IME 가 켜진 PC 에서
  사라지거나 한글로 바뀐다. 송장·상품 바코드는 숫자라 영향 없다. 정확한 접두어는 PR B 계획이 상품 바코드와 충돌하지 않는 값으로 정한다
- 숫자 0~9 명령은 「수량」 입력을 대신한다
- 시트는 **A4, OS 인쇄 대화상자**로 출력(송장 프린터에는 송장 용지가 걸려 있다). Code128 인코더는 순수 함수로 직접 둔다(의존성 0)

### 5.4 피드백

- Web Audio 로 네 가지 소리: 성공 · 오류 · 완료 · 명령. 음량·음소거는 설정
- 오류는 화면 테두리 빨강, 완료는 초록. 다음 스캔에서 사라진다

### 5.5 상태바

| 항목 | 표시 |
| --- | --- |
| 프린터 | 미설정 또는 마지막 출력 실패면 빨강 |
| 서버 | 연결 |
| 미전송 스캔 | 1 이상일 때만 노랑으로 `미전송 N` |
| 배치 진행 | F1·F2 에서 `B-1002 13/40` |

**스캐너 표시는 두지 않는다.** HID 리더기는 키보드라 연결 여부를 앱이 알 수 없다 — 모르는 상태를 초록으로 그리지 않는다.

### 5.6 키 입력

- 창 수준 keydown **캡처 단계**에서 F1~F12·Esc 를 처리하고 기본 동작을 막는다. 입력칸에 포커스가 있어도 기능키는 동작해야 한다
- WebView2 기본 단축키(F5 새로고침·F12 개발자 도구·F3 찾기·F7 캐럿 브라우징·F11 전체 화면)를 막아야 한다.
  ⚠️ 릴리스 빌드에서 F5 새로고침을 확실히 막을 수 있는지는 **실기 확인 대상**(§10). 막을 수 없으면 해당 키를 재배정한다
- 대기 상태에서 사람이 숫자를 치기 시작하면 직접 입력칸이 열린다(별도 키 없음). 스캔 버퍼의 속도 판정이 사람 타이핑과 스캔을 가른다

## 6. F1 출고 검수

### 6.1 쓰는 서버 계약

**위치 없는 단순 출고 계약**을 쓴다(U5).

- 송장 스캔: `GET shipments/by-waybill`(조회 전용, 아무것도 바꾸지 않는다)
- 상품 스캔: `POST shipments/:id/simple-outbound-scans` — 준비(claim)·피킹·검수·마지막이면 자동 출고를 한 트랜잭션. **첫 상품 스캔이 곧 출고 준비**라
  U4 가 별도 시작 호출 없이 성립한다
- 강제출고: `POST shipments/:id/simple-outbound-forces`(§7.4)
- 위치 확인 출고(`location-outbound-*`)는 스테이션이 더 이상 부르지 않는다. 서버 엔드포인트 삭제는 별도 contract PR(§12)

### 6.2 화면 상태

송장 스캔 결과로 화면 상태를 정한다. 판정은 **순수 함수**(조회 결과 + 이벤트 → 화면 상태)로 두고 표 테스트한다.

| 조회 결과 | 화면 | 작업자 |
| --- | --- | --- |
| `labelState` `current`·`external` | **검수 중** | 상품을 찍는다 |
| `never_printed`·`reprint_required` | **새 송장 출력됨**(프린터 설정 시 **자동 출력**, 바뀐 줄 표) | 옛 송장을 버리고 새 송장을 찍는다 |
| `withdrawing` | **뺄 상품** | 담은 상품을 찍어 되돌림 바구니로 |
| `withdrawn` | 빠진 박스 | 송장을 버린다 |
| `not_started` · 오늘 배치에 없음 · 이미 출고 · 다른 창고 · 조회 실패 | 거절(오류음 + 사유 한 줄) | — |
| (스캔 없음) | **송장 대기** | 송장을 찍는다 |

- 자동 출력은 지금의 단건 출력 경로(`printOneLabel`: 렌더 → 프린터 → 출력 확인)를 쓴다. 프린터가 없으면 «프린터 있는 자리에서 출력»
- 같은 송장을 다시 찍으면 다시 조회한다. 몇 번을 찍어도 서버 상태는 바뀌지 않는다(#986 스펙 §10.5)

### 6.3 검수 중

- **스캔 1회 = +1.** F7 수량 → 숫자(키보드 또는 숫자 명령) → 다음 스캔 한 번에 그 수량
- **F8 이 상품 전량**: 직전에 찍은 줄의 «주문 − 스캔» 을 수량으로 그 바코드를 한 번 더 스캔한다(서버에는 일반 스캔). 직전 스캔이 없으면 꺼짐
- 박스에 없는 상품·주문 초과: 서버 거절 → 오류음·빨간 테두리, 진행 수량 그대로
- 마지막 상품: 서버가 같은 트랜잭션에서 출고 → 완료음 → **송장 대기**(직전 박스 완료 표시)
- 작업 중 다른 송장 스캔: 내려놓기 + 그 송장 열기(U13). 찍은 수량은 서버에 남는다
- Esc 내려놓기: 송장 대기로
- 스캔 큐·복구는 지금 것(`useWorkScanQueue`, 영속 오퍼레이션 실행기)을 그대로 쓴다. 불확실하면 상태바 `미전송 N`

**검수 중 기능키**

| 키 | 액션 | 조건 |
| --- | --- | --- |
| F7 | 수량 | |
| F8 | 이 상품 전량 | 직전 스캔 있음 |
| F9 | 결품 | 덜 찍힌 줄 있음, 결품 스코프 |
| F10 | 강제출고 | 강제출고 스코프 |

### 6.4 화면 구성(목업 ②)

- 왼쪽: 송장번호(크게) · 받는 분 · 배송메모(있을 때만, 강조) / 지금 찍을 것 + 진행 `2 / 6`(거대)
- 오른쪽: 품목 표 `위치 | 상품(옵션) | 주문 | 스캔` — 완료 줄 회색, 진행 줄 노랑, 수량 2 이상은 `×N` / 최근 스캔
- 위치 열은 **보여 주기만** 한다(입력 아님)

## 7. 결품·보충 대기·강제출고

### 7.1 F9 결품

1. 덜 찍힌 줄이 «주문 − 스캔» 으로 미리 채워져 뜬다. ↑↓ 줄 선택, 숫자로 줄이기(상한 = 남은 수량)
2. 사유: 기본 `inventory_shortage`, 숫자 2 → `item_damaged`(U10)
3. Enter 확정 → `POST shipments/:id/short-picks`
4. 결품 위치: 그 줄의 배정 위치가 하나면 그것, 여럿이면 **송장 순서상 마지막 위치**(U11)

결품 위치 결정도 순수 함수로 두고 표 테스트한다.

### 7.2 결과

| 응답 `outcome` | 화면 |
| --- | --- |
| `refilled` | 새 송장 **자동 출력** → 가져올 것(`[C-07-1] 퍼머넌트 1제 ×1`)을 잠깐 보이고 송장 대기로. 박스는 보충 대기 |
| `withdrawing` | 뺄 상품 화면 |
| `exited` | 빠진 박스 |

### 7.3 보충 대기

- 송장 대기 화면 오른쪽, 최근 스캔 위. 비어 있으면 그리지 않는다
- 행: 송장번호 · 받는 분 · 가져올 것(로케이션·상품·수량)
- **창고 단위 서버 조회**(§9 A6) — 어느 스테이션에서 봐도 같다. 박스가 출고되거나 빠지면 사라진다
- 이어 하기 = 새 송장 스캔(별도 동작 없음)

### 7.4 강제출고(F10)

- 기존 `simple-outbound-forces`: 남은 미피킹 수량을 배정 기준으로 채우고 강제 출고. 감사 로그는 기존 그대로
- 사유 입력칸 없음 — **고정 사유** `station_force_command`. 사후 점검은 강제출고 기록 목록으로
- 한 번 더 눌러 확정한다(F10 두 번 또는 강제출고 명령 두 번)

## 12. 범위 밖과 알고 남기는 틈

- **폰(핸드헬드) 화면 재설계** — 실사·이동 등 «움직이며 하는 작업» 부분집합(U3). 별도 트랙
- **`location-outbound-*` 엔드포인트와 `outboundContract` 분기 삭제** — 스테이션 전환 배포 뒤 contract PR
- **결품·파손이 원장을 줄이지 않는다**(#1005). 유령 재고는 실사·폐기 조정으로 바로잡힌다
- **나뉜 줄의 결품은 실제와 다른 위치로 기록될 수 있다**(U11) — 유령 재고가 실제로 모자란 위치가 아니라 마지막 위치에 남는다. 실사에서 바로잡힌다
- **위치별 원장의 정확도는 피커가 송장대로 집었는지에 달린다**(U5). 총량은 맞고, 위치 차이는 실사에서 드러난다
- **강제출고는 서버가 피해 범위를 제한하지 못한다**(U15). 다른 상품이 들어간 채로 나가도 시스템은 모른다 — 사후 점검이 유일한 방어
- **송장 재출력 뒤 옛 송장을 스캔해도 구별할 수 없다** — 재출력은 송장번호가 같고 판차만 바뀐다. 기존 #986 의 한계
- **보충 피커가 화면을 놓칠 수 있다**(U9). 실제로 문제가 되면 보충 쪽지 출력을 더한다
