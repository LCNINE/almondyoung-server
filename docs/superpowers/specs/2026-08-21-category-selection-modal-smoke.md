# 카테고리 선택기 수동 스모크 체크리스트 (#686)

- 설계: `2026-08-21-category-selection-modal-design.md`
- 대상 화면: 상품 상세 → 기본정보 탭 → `기본 정보 수정` 서랍 → 카테고리 선택 모달
- 회귀 대상: `/mall/categories`(카테고리 관리), 상품 목록 카테고리 필터

## 왜 이 문서가 필요한가

`apps/admin-web` 은 **`.tsx` 에 자동 검증이 거의 없다**:

| 게이트 | `.ts` | `.tsx` |
|---|---|---|
| `npx jest` | ✅ | ❌ transform 이 `^.+\.(t|j)s$` |
| `npm run lint` | ✅ | ❌ glob 이 `{src,apps,libs,test}/**/*.ts` |
| `npm run type-check` | ✅ | ✅ |

즉 **`.tsx` 에 걸리는 자동 게이트는 `type-check` 하나뿐**이다. 이 작업은 판정 가능한
규칙을 전부 `.ts` 순수 함수로 내려 그 구멍을 우회했지만(51개 테스트), **배선이 실제로
살아 있는지**는 사람이 눌러봐야만 알 수 있다. 아래 항목은 생략 가능한 확인이 아니라
이 변경의 **유일한 방어선**이다.

## A. 기본 흐름

- [ ] **A1** 카테고리 여러 개 선택 → `적용` → 서랍 요약 줄에 반영 → 저장 → 상세에 반영
- [ ] **A2** 이미 카테고리가 붙은 상품으로 모달 재진입 →
      **선택된 것들의 조상이 펼쳐져 있는지** (안 펼쳐지면 뭘 골라놨는지 안 보인다)
- [ ] **A3** 선택됨 패널의 `제거`(×) 와 `대표`(★) 동작
- [ ] **A4** 트리 행의 `대표` 버튼 — 선택된 행에만 나타나는지

## B. 검색

- [ ] **B1** `바디 크림` 처럼 **공백 넣어** 검색 → 매치가 좁혀지는지
- [ ] **B2** `화장품` 처럼 **루트 이름** 검색 → **트리가 폭발하지 않는지**
      (자손 수백 개가 딸려 나오면 실패)
- [ ] **B3** 검색어를 지웠을 때 **자동 펼침만 사라지고 사용자가 직접 펼친 것은 남는지**
- [ ] **B4** 검색 중 이미 선택된 상위 행이 **체크된 채 잠긴 회색**으로 보이는지
      (체크 해제된 것처럼 보이면 UI 가 상태를 속이는 것)

## C. 비활성 필터

- [ ] **C1** `비활성 포함` 을 껐을 때 **비활성 부모 아래 활성 자식이 여전히 보이는지**
- [ ] **C2** 이미 선택된 비활성 카테고리를 **뗄 수 있는지**
      (토글을 꺼도 항상 보여야 한다 — 아니면 잘못 붙은 걸 못 뗀다)

## D. 키보드 — 위험이 실린 구간

- [ ] **D1** 검색창에서 `↓` → 트리 첫 항목 진입 → `↑↓` 이동 → `Space` 선택 → `적용`
- [ ] **D2** `Esc` 로 닫기 (서랍 위 다이얼로그의 **포커스 트랩**이 정상인지)
- [ ] **D3** `←` `→` 로 접기/펼치기, 접힌 상태에서 `←` 가 부모로 가는지
- [ ] **D4** 🔴 **긴 목록에서 `↑↓` 를 계속 눌렀을 때 포커스 행이 화면 안으로 따라오는지**
      — Radix `ScrollArea` 뷰포트 안에서 `scrollIntoView` 가 실제로 먹는지는
      코드로 확정 못 했다(구조상 가능까지만 확인)
- [ ] **D5** 🔴 **체크박스를 마우스로 클릭한 뒤 `Space` 를 눌러 이중 토글이 나는지**
      — `tabIndex={-1}` 은 Tab 순서에서만 빼고 **클릭 포커스는 막지 않는다.**
      네이티브 버튼 활성화와 트리의 Space 처리가 겹칠 수 있다
- [ ] **D6** 행을 마우스로 클릭한 뒤 `↑↓` → **클릭한 자리에서 이어지는지**
      (직전 키보드 위치에서 재개하면 실패)
- [ ] **D7** 화살표로 아래까지 내려간 뒤 **검색창에 타이핑** → 목록이 무관한 행으로
      튀지 않는지
- [ ] **D8** 잠긴(흐린) 행에 포커스를 두고 `Space` → 선택이 안 바뀌고 스크롤도 안 튀는지

## E. 레이아웃

- [ ] **E1** 전체화면 시트(96vw × 92vh)가 화면 크기를 따라가는지 (고정 높이 잔존 없음)
- [ ] **E2** **창을 좁혀서**(`lg` 미만) 두 패널이 쌓일 때 트리 높이가 무너지지 않는지
- [ ] **E3** 깊은 계층에서 들여쓰기 때문에 라벨이 과도하게 잘리지 않는지
- [ ] **E4** 포커스 링이 라이트/다크 양쪽에서 보이는지

## F. 회귀 — 이 변경이 건드린 남의 화면

- [ ] **F1** 🔴 **`/mall/categories` 카테고리 관리** — 드래그앤드롭 이동, 검색,
      펼침/접기, 저장. **이 페이지는 스펙이 0건이라 jest 가 회귀를 못 잡는다.**
      트리 펼침 훅 내부가 통째로 교체됐다
- [ ] **F2** 관리 페이지에서 **단일 토큰 검색**이 예전과 같은 결과를 주는지
- [ ] **F3** 상품 목록의 카테고리 필터(평탄한 Select)가 그대로 동작하는지

## G. 스크린리더 (가능하면)

- [ ] **G1** `aria-level` 로 계층이 읽히는지, `aria-multiselectable` 이 다중 선택으로
      안내되는지 — ARIA 명세상 구조는 맞으나 실제 AT 확인은 못 했다

## 알려진 한계 (스모크 실패로 오인하지 말 것)

- **DOM 은 평탄한 형제 구조**다(중첩 `role="group"` 없음). `aria-level` 로 계층을
  전달하며, `aria-setsize`/`aria-posinset` 은 이번 범위 밖으로 뒀다
- **가상화 없음.** 트리가 기본 접힘이라 초기 렌더는 옛 평탄 목록보다 오히려 가볍지만,
  `모두 펼치기` + 수백 노드 상태에서 체크박스 클릭 하나가 O(n) 재계산이다
- **카테고리별 상품 수는 표시하지 않는다** — `CategoryDto` 에 필드가 없어 백엔드 작업이
  필요하고 이번 범위 밖이다
- **관리 페이지 검색 하이라이트가 다중 토큰 매치에서 `<mark>` 를 못 붙인다.**
  행은 굵어지지만 강조 구간이 없다. 매처가 넓어진 데 비해 `highlight()` 가 원문
  부분일치를 그대로 쓰기 때문 — 우아하게 퇴화하며 후속 이슈감
- **트리에 없는 카테고리**(삭제된 것 등)가 상품에 붙어 있으면 선택됨 패널에 raw UUID 가
  보이고, 아무 항목이나 토글하는 순간 그 id 가 떨어진다. 옛 코드도 체크 시엔 같았다
