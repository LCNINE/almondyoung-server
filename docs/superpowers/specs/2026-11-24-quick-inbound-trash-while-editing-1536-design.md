# 간편입고 — 수량 수정 중에도 휴지통이 눌린다 (#1536)

## 왜

스테이션 F3 간편입고에서 상품을 담은 뒤 휴지통이 안 눌렸다. 수정 취소를 누른 뒤에야 눌렸다.
`QuickInboundScreen.tsx` 의 삭제 버튼이 `!!editing` 이면 disabled 인데, 상품 검색에서 고르면
(`chooseSku`) 그 줄을 담자마자 수량 수정이 자동으로 열린다. 그래서 «잘못 골랐다 → 지운다» 의
가장 흔한 순간에 휴지통이 잠겨 있다. 버튼 색도 그대로(`text-gray-400`)라 잠긴 줄 모르고 고장으로 보인다.

## 목표 / 비목표

- 목표: 수정이 열려 있어도 어느 줄이든 휴지통으로 지울 수 있다. 잠긴 버튼은 잠긴 티가 난다.
- 비목표: 수정 흐름(자동 열림·수량 저장·수정 취소) 자체를 바꾸지 않는다. 다른 화면은 건드리지 않는다.
- 반목표: 휴지통이 입력 중이던 다른 줄의 숫자를 말없이 날리면 실패다.

## 접근

| 안 | 내용 | 판정 |
|---|---|---|
| A (채택) | 휴지통은 `editing` 으로 잠그지 않는다. 지운 줄이 수정 중인 줄이면 수정을 닫고, 다른 줄이면 수정창·입력값을 그대로 둔다 | 현장 증상(방금 고른 줄 지우기)을 고치고 입력도 안 잃는다 |
| B | 수정 중인 줄만 잠근다 | 기각 — 지우려는 줄이 바로 수정 중인 줄이라 증상이 그대로다 |
| C | 휴지통을 누르면 무조건 수정을 닫고 지운다 | 기각 — 다른 줄을 지울 때 입력 중이던 숫자를 잃는다 |

## 설계

- 삭제 버튼 disabled 조건에서 `!!editing` 만 뺀다(`!reconciled`·`!draft.ready`·`scanQueue.blocked()`·`submit.isPending`·`saving` 은 유지).
- 삭제가 저장된 뒤, 지운 줄이 `editing` 이었으면 `setEditing(null)`. 저장이 실패하면 수정 상태도 그대로 둔다.
- 수량 버튼은 `editing` 중 계속 잠근다(다른 줄로 옮기면 입력값이 사라진다). 대신 휴지통·수량 버튼 둘 다 `disabled:opacity-40` 으로 잠긴 티를 낸다.
- 다른 입고 화면(예정 입고·적치 대기·발주 입고)에는 줄 삭제·줄별 수량 수정이 없어 같은 패턴이 없다(2026-11-24 확인). 재고조사의 수정은 별도 시트라 해당 없음.

## 검증

`QuickInboundScreen.test.tsx` 에 두 건:
1. 상품을 고른 직후(수정 열림) 휴지통이 눌리고, 그 줄이 지워지며 수정창이 닫힌다.
2. 한 줄을 수정하며 숫자를 입력한 상태에서 다른 줄을 지우면, 수정창과 입력값이 남는다.

게이트: `cd native/warehouse-app && npx tsc -b && npx vitest run`.
