# 셀메이트 바코드번호2 를 core 보조 바코드로 (#1356) — 설계

상위: #1233 (컷오버 1단계). 크기: 작은 변경.

## 왜

T 다음 날부터 피킹·검수·입고 스캔은 core 가 `sku_barcodes` 에서 찾는다
(`apps/core/src/modules/fulfillment/services/sku-barcode-resolution.ts`). 셀메이트에서 스캔되던
`바코드번호2` 가 core 에 없으면 그 상품은 T 부터 «모르는 바코드»가 된다.

`scripts/sellmate/import-products.ts` 의 `COLUMN_CANDIDATES.barcode` 는 헤더에서 열을 **하나만** 고른다.
실제 «현재고 전체» CSV 에는 `바코드번호`·`바코드번호(서식)`·`바코드번호2` 가 모두 있으므로
`바코드번호2` 는 한 번도 읽히지 않는다.

입력 파일 실측(2026-10-16 내보내기, 33,920행): `바코드번호2` 가 찬 행 3,475, 그중
`바코드번호(서식)` 과 같은 값 2,047, 다른 값 1,428. 파일 안에서 `바코드번호2` 값 중복 0, `="…"` 감싸기 0.
값은 대부분 제조사 EAN-13(`880…`)이다. 라이브 대조 수치는 백필 dry-run 이 다시 잰다.

## 목표 / 비목표

- 목표: 가져오기가 `바코드번호2` 를 보조 바코드(`is_primary=false`)로 넣는다. 이미 적재된 SKU 에 한 번 백필한다.
- 비목표: 대표 바코드 규칙 변경. 충돌 자동 해소(사람이 목록을 보고 정한다).
- 비목표: 이슈의 «남는 의문»(내보내기에 안 나오는 바코드 칸) 현장 확인. 그래서 PR 은 `Refs #1356` 이고 이슈를 닫지 않는다.
- 안티 목표: 백필이 대표 바코드를 내리거나 SKU 이름·그룹을 건드리는 것.

## 접근

검토한 길:

1. **(채택) 보조 바코드 판정을 순수 함수 하나로 두고, 가져오기와 별도 백필 스크립트가 함께 쓴다.**
   백필은 보조 바코드만 넣는다.
2. 고친 `import-products.ts` 를 다시 돌려 백필한다. 같은 결과지만 SKU 이름·그룹 upsert 와
   대표 바코드 내리기(`:394`)까지 따라와 백필 범위를 넘는다.
3. 판정 스크립트(`scripts/ops/cutover-preflight`)에 «바코드번호2 중 core 에 없는 것» 검사를 넣는다.
   **사용자 결정으로 넣지 않는다** — 판정 스크립트는 DB 만 읽고 파일 입력이 없다. 백필 dry-run 의
   «core 에 없음» 수가 그 역할을 한다.

## 정한 규칙

- 열: `바코드번호2` 를 별도 논리 열(`barcode2`, 후보 `바코드번호2`, 오버라이드 `COL_BARCODE2`)로 읽고 `unwrapFormula` 를 거친다. 열이 없는 양식이면 지금처럼 동작한다.
- 같은 행의 대표 바코드와 값이 같으면 건너뛴다.
- 대표 바코드가 비어 있어도 `바코드번호2` 를 대표로 올리지 않는다(«대표 규칙은 그대로»). 라벨은 대표가 없으면 먼저 만든 바코드를 쓴다(`inventory-labels.reader.ts:44`).
- 이미 같은 SKU 에 달려 있으면(대표든 보조든) 그대로 둔다 — 멱등.
- 다른 SKU 가 점유한 값은 넣지 않고 충돌로 보고만 한다.
- 한 실행 안에서 같은 값을 두 SKU 가 원하면 **대표 바코드가 먼저** 차지한다(대표를 먼저 배정한 뒤 보조를 배정).
- `packing_unit` 은 NULL(한 번 스캔 = 낱개 1). 셀메이트도 그렇게 셌다고 본다.
- 제외 품목(`excluded.ts`)은 건너뛴다. 넣기는 `ON CONFLICT (barcode) DO NOTHING`.

## 백필 스크립트 `scripts/sellmate/backfill-barcode2.ts`

- 입력: «현재고 전체» CSV 경로. `옵션정보일련번호` → `skus.code` 로 SKU 를 찾는다.
- 기본 dry-run(읽기 전용 트랜잭션), `--apply` 로 반영. `register-missing-barcodes.ts` 의 CLI 모양(`DRY_RUN` 과 `--apply` 동시 거부)을 따른다.
- 출력: 넣을 것 / 이미 같은 SKU / 다른 SKU 점유(충돌, 목록) / core 에 SKU 없음 — 각각 재고 있는 SKU 수를 붙인다.
- 테넌트 1 core DB 에만 돈다(셀메이트는 테넌트 1 의 것). `run.sh live backfill-barcode2 <csv>` 로 부른다.
- 순서: 이 백필 → `register-missing-barcodes`(바코드 행이 하나도 없는 SKU 만 보므로).
- `--apply` 전에는 최신 «현재고 전체» 를 다시 받는다 — 10-16 파일 뒤에 생긴 SKU 는 빠진다.
