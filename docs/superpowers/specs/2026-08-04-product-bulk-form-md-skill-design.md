## 1. 목표

일괄등록 양식은 시트 간 참조 키가 넷인 **정규화된 관계 모델**이고, 수정용 프리필 양식에서는 그 키가 raw UUID 로 노출된다(§2.1). 비개발자인 MD 가 손으로 다루기 어렵다.

MD 가 Claude Desktop 에서 AI 에게 양식 작성을 맡길 수 있도록, **카탈로그 도메인과 이 양식의 계약을 정확히 담은 스킬**을 만든다. 그리고 AI 가 양식을 다룰 때 발생 가능한 치명적 사고 하나를 서버에서 구조적으로 막는다.

목표 유스케이스 셋:

1. MD 가 자기 형식으로 정리해 둔 상품 데이터를 우리 양식으로 옮긴다
2. 프리필 양식을 받아 대량 수정한다 (예: A 카테고리 상품 전량을 B 카테고리로 이동)
3. 타 몰에서 수집한 데이터를 신규 등록 양식으로 정리한다 (이미지 포함)

### 1.1 비목표

- **MCP 커넥터**: 양식 다운로드·업로드·오류 조회까지 AI 가 직접 하는 경로. 배포 문제까지 함께 푸는 진짜 졸업 경로지만(§7), 이번에는 하지 않는다. 스킬로 개념을 먼저 검증한다
- **admin-web 내장 AI 편집 화면**: 범위 밖
- **서버 검증 규칙의 미러링**: 스킬은 양식 무결성만 보고 비즈니스 규칙은 서버에 맡긴다(§3.4)
- **재고·매칭·채널 연동 지식**: 양식으로 건드릴 수 없는 것을 AI 가 알면 MD 에게 할 수 없는 일을 제안하게 된다

## 2. 현재 상태 실측 (2026-08-04, `9331f7a88`)

### 2.1 양식은 관계 모델을 그대로 노출한다

워크북은 7 시트 + 숨은 `_양식정보` 시트다(`form-export.workbook.ts:42-71`). 시트를 잇는 참조 키가 넷이다.

| 참조 키 | 프리필 시 실제 셀 값 | 근거 |
|---|---|---|
| `상품키` | `P-000001` — 상품·옵션·조합·카테고리·구매제약 5시트를 잇는다 | `form-export.snapshot.reader.ts:128` |
| `옵션키` | `product_option_groups.id` — **uuidv7 원본** | `:243`, `catalog.schema.ts:455` |
| `옵션값키` | `product_option_values.id` — **uuidv7 원본** | `:246`, `catalog.schema.ts:463` |
| `조합` | 옵션값 uuid 를 정렬해 `+` 로 이은 문자열 | `:268-271` |
| `이미지키` | `IMG-1` — 대표·부가(`|` 구분)·본문 디렉티브에서 참조 | `form-export.sheets.ts:38-39` |

사람이 읽을 수 있는 `조합명(참고용)`(`색상=빨강;사이즈=S`)이 옆에 있으나 **파서가 읽지 않는 참고 열**이다(`:272`).

여기에 형식 규약이 더 붙는다: 다중값 `|` 구분(부가이미지키·SEO키워드), 불리언 `Y`/`N`, 날짜 KST 문자열, 복합 가격규칙 센티넬 `[복합 가격규칙]`(`form-export.sheets.ts:13`).

워크북에는 **안내 시트도 드롭다운도 데이터 유효성 검사도 없다.** 서식은 필수 헤더 볼드 + 헤더 행 고정이 전부다(`form-export.workbook.ts:18-33`).

### 2.2 `exportId` 부재는 조용히 "신규 전용"으로 읽힌다 — 대량 중복 벡터

`_양식정보`(veryHidden) 시트의 `exportId` 하나가 "이 워크북은 수정용"임을 말하는 **유일한 표식**이다. 업로드 시 분기는 셋이다(`bulk-session.manager.ts:108-114`, `assertExportUsable`:172):

| `exportId` | 처리 |
|---|---|
| 있고 해석됨 | 정상 수정 |
| 있는데 해석 안 됨 | 업로드 거부 (모체 스펙 §3.1 이 의도적으로 넣은 안전장치) |
| **없음** | **신규 전용 세션** |

세 번째 분기가 문제다. 프리필 워크북에서 숨은 시트가 유실되면 `P-000001` 부터의 모든 행이 **신규 상품으로 재생성**된다. 그리고 `상품키` 검증은 varchar 길이 100 뿐이라 `P-` 형식을 아무도 막지 않는다(`bulk-session.validator.ts:27`).

유실 경로는 AI 에 국한되지 않는다. 사람이 시트를 복사해 새 파일로 옮겨도 같은 사고가 난다.

### 2.3 조합 중복 판정은 문자열 원본이다

`checkCreateStructure` 는 조합을 `combo.split('+')` 로 쪼개 각 키가 옵션 시트에 있는지 보고, **중복은 조합 문자열 원본으로** 센다(`bulk-draft.options.ts:216-234`).

따라서 `A+B` 와 `B+A` 는 서로 다른 조합으로 둘 다 통과해 **같은 논리적 조합의 품목이 둘 생긴다.** 프리필은 항상 정렬해 쓰므로(§2.1) 이 사고는 신규 행에서만 난다.

### 2.4 오류 되먹임 루프가 끊겨 있다

검토 화면의 오류는 행을 펼쳐야 보이는 인라인 텍스트고 복사도 내려받기도 없다(`review-panel/item-row.tsx:66-71`). 업로드 결과 오류가 나오면 MD 가 AI 에게 되돌려줄 방법이 화면 캡처나 수기 전사뿐이다.

행 목록 조회는 `status`·`conflict`·`publishStatus` 필터와 페이지를 지원하지만 **`limit` 이 100 으로 클램프된다**(`bulk-session.controller.ts:45-47`). 이 저장소는 이미 이 함정을 한 번 밟았다 — 발행 패널이 `limit=1000` 을 보냈다가 조용히 잘려 실패 행이 유실됐고, 그래서 `publishStatus` 서버 필터가 추가됐다(`bulk-session.reader.ts:44` 주석).

### 2.5 스킬 런타임 제약 (공식 문서 실측)

[Agent Skills 문서](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview) 기준:

- **실행 스크립트 번들은 정식 패턴이다.** `scripts/`·`references/`·`assets/` 구조이며, 스크립트는 bash 로 실행되고 **코드는 컨텍스트에 들어가지 않고 출력만 들어간다**("providing deterministic operations without loading their code into context")
- **claude.ai(= Claude Desktop) 커스텀 스킬은 zip 업로드이고 사용자별이다.** "Custom Skills are individual to each user. They are not shared organization-wide and cannot be centrally managed by admins." 코드 실행이 켜져 있어야 한다
- **네트워크 접근은 가변이다.** "Depending on user/admin settings, Skills may have full, partial, or no network access"

세 번째가 이미지 URL 다운로드 가능 여부를 좌우한다(§3.7).

### 2.6 exceljs ↔ openpyxl 왕복은 안전하다 (실증)

우리 워크북과 같은 구조(veryHidden 메타 시트 + 보호된 참조 시트 + 볼드 헤더 + 틀고정)를 exceljs 로 만들고, openpyxl 로 열어 셀 하나만 고쳐 저장한 뒤, **우리 파서와 같은 exceljs 로 되읽었다.**

```
_양식정보 존재: true   state: veryHidden   B1 값: 보존됨
편집한 셀: 반영됨      안 건드린 셀: 보존됨
헤더 볼드: 유지        틀고정: 유지
```

§3.4 의 "원본을 열어 셀만 갈아끼운다" 기제가 성립한다.

### 3.1 산출물 넷

### 3.2 ① 예약 상품키 가드 (core)

`P-` + 숫자 6자리를 **시스템 발급 예약 형식**으로 못박고, 이 형식의 상품키는 반드시 해당 세션의 양식 잡 매핑에서 해석돼야 한다는 규칙을 넣는다.

| 상황 | 처리 | 위치 | 이유 |
|---|---|---|---|
| `exportId` 없는데 `P-\d{6}` 행이 있음 | **파일 전체 거부 (400)** | `bulk-session.manager.ts` `accept()` | 숨은 시트를 잃은 수정용 양식이다. 사고 규모가 크고 원인이 하나(잘못된 파일)라 행 단위로 쪼갤 이유가 없다 |
| `exportId` 는 해석됐는데 그 `P-…` 키가 매핑에 없음 | **행 오류 (invalid)** | `bulk-session-job.manager.ts:388` 근처 | 서로 다른 양식의 시트를 섞은 경우다. 나머지 행은 정상 진행할 수 있다 |

**파일 수준 게이트를 `accept()` 에 두는 근거**: 이 메서드에는 이미 "파일 수준 게이트는 여기서 동기로 친다"는 규약과 그 근거가 문서화돼 있고(`:84-88`), `parseUploadWorkbook` 결과를 손에 쥔 상태다. 세션을 만들기 **전에** 막아야 하는 사고라는 점도 기존 `assertExportUsable` 과 같다.

**행 수준 게이트를 job manager 에 두는 근거**: 그 지점이 `knownRows`(양식 잡 매핑)를 조회해 수정 행의 기준을 찾는 자리다.

**부수 효과**: 빈 양식에서 MD 가 상품키를 `P-000001` 로 짓는 것도 막힌다. 이는 의도한 동작이다 — 시스템 발급 키와 사람이 지은 키가 같은 공간을 쓰면 반드시 혼동이 생긴다. 오류 메시지가 다른 형식을 쓰도록 안내한다.

이 가드는 AI 와 무관하게 사람이 시트를 복사해도 나는 사고를 막으므로 스킬이 없어도 가치가 있다.

### 3.4 두 도구의 계약

**`read_form.py` 의 본질은 조인이다.** 6개 시트를 상품키로 묶어 상품 하나가 객체 하나가 되게 만든다. AI 가 시트 간 참조를 손으로 따라다니지 않게 되고, 이것이 §2.1 의 어려움을 없애는 핵심이다.

```json
{
  "exportId": "0198…",
  "products": [{
    "상품키": "P-000001",
    "출처": "프리필",              // "프리필" | "신규" — 상품키가 양식 잡 매핑에 있으면 프리필
    "필드": { "상품명": "…", "판매가": "10000" },
    "옵션": [...], "조합": [...], "카테고리": [...], "구매제약": null
  }],
  "고아행": [],                    // 상품 시트에 없는 상품키를 가리키는 자식 행 (개정 2026-08-05)
  "이미지": [...],
  "카테고리참조": ["여성패션>니트", "…"]
}
```

**`write_form.py` 는 전체 상태가 아니라 변경분을 받는다.** 이것이 "AI 가 실수로 필드를 비우는" 사고를 구조적으로 없앤다.

| JSON | 결과 |
|---|---|
| 키를 아예 안 적음 | 셀을 건드리지 않음 → (프리필 행이면) 변경 없음 |
| `{"브랜드": null}` | 셀을 비움 → **명시적 비움** |
| `{"브랜드": "ACME"}` | 값을 씀 |

모체 스펙 §3.5 의 3-way 의미가 JSON 문법에 그대로 얹힌다 — **비우려면 `null` 을 명시해야 하므로 우연한 비움이 불가능하다.**

```json
{
  "변경": [{ "상품키": "P-000001",
             "필드": { "브랜드": "ACME", "소재": null },
             "카테고리": [{ "카테고리경로": "여성패션>가디건", "대표여부": "Y" }] }],
  "신규":  [{ "상품키": "NEW-001",
             "필드": { "상품명": "…", "판매가": "19900" },
             "옵션": [{ "옵션키": "OPT-색상", "옵션명": "색상",
                        "옵션값키": "OV-빨강", "옵션값명": "빨강" }],
             "조합": [{ "조합": ["OV-빨강"], "품목코드": "SKU-1" }],
             "카테고리": [{ "카테고리경로": "여성패션>니트", "대표여부": "Y" }] }],
  "이미지": [{ "이미지키": "IMG-10", "원본": "NEW-001-main1.jpg" }]
}
```

**`조합` 은 문자열이 아니라 배열로 받고, `write_form.py` 가 정렬해 `+` 로 잇는다.** §2.3 때문이다 — AI 가 문자열을 직접 만들면 `A+B`/`B+A` 가 갈려 같은 조합의 품목이 둘 생긴다. 정렬 책임을 도구가 가져가면 이 사고가 나올 자리가 없다.

시트 행 목록(`옵션`·`조합`·`카테고리`)을 주면 그 상품의 해당 시트 행을 **교체**하고, 안 주면 건드리지 않는다. 다만 **프리필 행에서 `옵션`·`조합` 교체는 §3.5 규칙 2·6 이 금지한다** — 구조가 스냅샷과 다르면 서버가 행 오류로 떨군다(`bulk-session.structure.ts:55` `checkOptionStructure`). 두 시트의 교체가 의미를 갖는 것은 신규 행뿐이고, 프리필 행에서 실제로 바꿀 수 있는 것은 표시명·색상·정렬이다.

**저장 직전 자체 검사** — 하나라도 불통과하면 파일을 만들지 않는다(fail-closed):

1. 원본에 있던 `_양식정보` 시트가 결과물에도 있는가
2. 필수 헤더가 전부 있는가
3. 모든 시트의 상품키가 상품 시트에 존재하는가
4. 조합의 각 키가 그 상품 옵션 시트의 옵션값키 집합 안인가
5. 카테고리 행이 있는 상품마다 `대표여부=Y` 가 정확히 1개인가
6. 신규 상품키가 예약 형식 `P-\d{6}` 이 아닌가
7. 이미지 `원본` 이 http(s) URL 이 아닌가
8. 상품키 중복이 없는가

전부 **양식 무결성**이고 비즈니스 규칙(가격·길이 상한·복합 가격규칙 판정)은 없다. 6번만 core 가드와 정규식을 공유하는데, 이 중복은 의도적이다 — 업로드 전에 알려주는 편이 낫고, 형식 예약이라 드리프트 위험이 사실상 없다.

> **개정 (2026-08-05, 최종 리뷰 반영)**: 3·4·5 는 **이번 변경이 손댄 상품키(`변경`+`신규`)에만 fail-closed** 다. 그 밖의 행에서 발견한 같은 조건은 경고로 호출자에게 돌려주고 파일은 만든다 — 서버가 그 조건들을 행 단위로만 떨구고 세션은 진행시키는데(`bulk-upload.assembler.ts:81-88`, `bulk-session.structure.ts:267-269`), 워크북 전체를 막으면 AI 가 건드리지도 않은 레거시 행 하나가 파일 생성을 전부 막고 이 스크립트에는 행 삭제 기능도 새 워크북 생성 경로도 없어 빠져나갈 길이 없다(위 §3.4 가 피하려던 "스킬이 유효한 작업을 막음"). 1·2·6·7·8 은 전역 그대로다. 4 에는 "옵션 행이 있는 상품인데 조합 칸이 빈 경우"가 추가됐다(빈 조합은 옵션 없는 상품의 단일 기본 품목이라는 계약이 있어 무조건 막을 수는 없다 — `bulk-draft.options.ts:216`). 6 의 두 문구는 `had_meta` 가 아니라 **원본 워크북에 있던 키인가**로 갈린다 — 빈 양식은 정상적으로 `_양식정보` 가 없다(`form-export.workbook.ts:64-70`).

### 3.5 `SKILL.md` 절대 규칙

짧아야 지켜진다. 상단에 이것만 둔다.

1. 워크북을 새로 만들지 않는다 — `write_form.py` 만 쓴다. `pandas.to_excel`·새 `Workbook()` 금지
2. 프리필 행의 `상품키`·`옵션키`·`옵션값키`·`조합` 은 **읽기 전용**이다
3. 지시받지 않은 필드는 JSON 에 담지 않는다
4. 비우려면 `null` 을 명시한다 — 확신이 없으면 비우지 말고 MD 에게 묻는다
5. `[복합 가격규칙]` 이 든 칸은 건드리지 않는다
6. 프리필 행에서 옵션값·조합 추가·삭제는 **불가능**하다 — 요청받으면 "양식으로는 안 되고 상품 상세 화면에서 해야 한다"고 답한다
7. 이미지 `원본` 에 URL 을 쓰지 않는다
8. **확보하지 못한 이미지가 있으면 조용히 넘어가지 않는다** — 경고하고, 누락 목록을 상품별로 보여주고, 조치 방법(상품 상세 화면에서 나중에 붙이기 / 파일 확보 후 재작업)을 명시한다(§3.7)

### 3.6 담는 지식의 범위

**"AI 가 MD 에게 정확히 설명하는 데 필요한 만큼"**으로 자른다.

담는다: 상품(master)/버전/draft/active/발행 관계, 옵션그룹→옵션값→조합 구조, 카테고리 경로와 대표 1개 규칙, 판매가/멤버십가/조합별 오버라이드, 이미지 3종 용도(대표·부가·본문 디렉티브), 업로드 후 MD 가 밟는 절차.

담지 않는다: 재고·매칭·채널 연동·주문. 양식으로 건드릴 수 없는 영역이며, AI 가 알면 MD 에게 할 수 없는 일을 제안하게 된다.

### 3.7 이미지 파이프라인

입력이 세 갈래이고 섞일 수 있다.

| 입력 | AI 가 하는 일 |
|---|---|
| MD 로컬 폴더에 이미 있음 | 파일명만 이미지 시트에 적는다 |
| URL 목록 (크롤링) | 내려받아 폴더를 만들고 그 파일명을 적는다 |
| 프리필의 기존 이미지 | **아무것도 안 한다** — 이미 fileId 로 해석돼 있고 건드리지 않으면 유지된다 |

파일명이 곧 admin-web 3단계의 매칭 키다(대소문자 무시·앞뒤 공백 제거). AI 가 붙이는 이름은 `<상품키>-<용도><순번>.<확장자>` 규칙을 쓴다 — 예: `NEW-001-main1.jpg`.

**전량 게이트가 만드는 규칙**: 3단계는 요구된 파일이 전부 채워져야 전진한다(모체 스펙 §3.9). 시트에 적힌 파일명이 하나라도 안 올라오면 세션이 그 자리에서 멈추고, 취소 말고는 나갈 길이 없다. 따라서 **확보하지 못한 이미지는 시트에 적지 않는다.** 빈칸으로 두고 나중에 상품 상세 화면에서 붙이는 편이 세션 전체를 막는 것보다 언제나 낫다.

다만 이것이 **조용한 누락이 되면 안 된다** — §3.5 규칙 8 이 경고·목록·조치 방법을 강제한다.

**네트워크가 막혀 있을 때의 대비책**: AI 가 직접 못 받으면 MD 가 로컬에서 실행할 다운로드 스크립트와 매니페스트를 대신 만들어 준다. 이미지 시트에는 어차피 **최종 파일명**을 미리 적을 수 있으므로, 다운로드 성공 여부와 무관하게 워크북은 완성된 상태로 나간다. 즉 네트워크 가부가 설계를 가르지 않고 절차 한 단계만 바꾼다.

### 3.8 ③ 열 레퍼런스 동기화

`columns.md` 의 진실은 `form-export.sheets.ts` 의 `ALL_COLUMN_SETS` 다. 손으로 베끼면 다음 열 추가 때 조용히 어긋나고, **어긋나도 아무 경고 없이 잘못된 양식이 나온다.**

생성기가 `ALL_COLUMN_SETS` 로 **두 파일**을 만들고, jest 테스트 하나가 "생성물 == 커밋된 파일"을 둘 다 비교한다.

- `references/columns.md` — AI 가 읽는 사람용 표
- `scripts/columns.json` — 두 스크립트가 읽는 기계용 라벨↔키 매핑

**스크립트가 라벨을 하드코딩하지 않는 것이 핵심이다.** 하드코딩하면 드리프트 지점이 문서와 코드 두 곳으로 늘어난다. 한 생성기가 둘을 만들면 드리프트가 0이 된다.

열을 추가하면 CI 가 깨지고, 깨진 것을 고치는 유일한 방법이 스킬 갱신이다.

### 3.9 ④ 「오류 목록 복사」 (admin-web)

검토 화면 헤더에 버튼 하나. `status=invalid` 로 **`limit=100` 페이지를 끝까지 돌아** 모으고, `행번호 · 상품키 · 상품명 · 사유` 를 줄 단위 텍스트로 클립보드에 넣는다. 시트명은 `errorMessage` 문자열 안에 이미 들어 있으므로 별도 열로 뽑지 않는다(`BulkSessionItem` 에 시트 필드가 없다).

§2.4 때문에 페이지 루프가 필수다 — `limit=1000` 을 보내면 조용히 100 으로 잘리고, 이 저장소는 그 사고를 이미 한 번 겪었다.

### 3.10 배포 패키징

claude.ai 커스텀 스킬은 **사용자별 zip 업로드이고 관리자 배포가 없다**(§2.5). 따라서:

- `npm run build:bulk-form-skill` 이 `skills/product-bulk-form/` 을 버전이 붙은 zip 으로 만든다
- MD 용 설치 안내를 `docs/manuals/` 에 둔다 (기존 `상품-등록-매뉴얼.md` 와 나란히)
- **`SKILL.md` 에 스킬 버전을 박고, AI 가 작업 시작 시 자기 버전을 말한다** — 낡은 zip 을 쓰는 MD 를 찾아낼 수 있는 유일한 수단이다

## 4. 실패 모드

| 실패 | 처리 |
|---|---|
| `write_form.py` 자체 검사 불통과 | 파일을 만들지 않고 사유를 반환 — AI 가 고쳐 재시도 |
| 원본 xlsx 없이 수정 요청 | 거부하고 "양식을 다시 받아오라"고 안내 — 숨은 시트를 복원할 방법이 없다 |
| 이미지 확보 실패 | 경고 + 누락 목록 + 조치 방법을 명시하고 시트에는 적지 않는다 |
| 업로드 후 서버 오류 | MD 가 「오류 목록 복사」 → AI 에게 붙여넣기 → 수정 → 재업로드 |
| 숨은 시트를 잃은 파일이 올라옴 | core 가 400 으로 거부 (§3.2) |
| 스킬이 낡음 | AI 가 말한 버전으로 식별 (§3.10) |

## 5. 테스트 전략

- **core 가드**: 기존 spec 파일에 단위 테스트 추가. 파일 수준(`exportId` null + `P-` 행 → 400), 행 수준(매핑에 없는 `P-` 키 → invalid), 그리고 `P-` 가 아닌 신규 키는 영향 없음
- **동기화**: jest 가 `ALL_COLUMN_SETS` → `columns.md` 생성물을 커밋본과 비교
- **스크립트 자체 로직**: pytest — 변경분 의미(미기재/`null`/값), 조합 정렬, 자체 검사 8항목
- **상호운용 왕복**: exceljs 로 워크북 생성 → 파이썬 스크립트로 편집 → exceljs 로 검증. §2.6 실험을 고정 테스트로 만든다. **진짜 위험은 스크립트 내부가 아니라 두 라이브러리 사이의 왕복이라 이 테스트의 값이 가장 크다**

CI 에 파이썬이 없으면 뒤 둘은 스킵하고 로컬에서 돌린다. 동기화 테스트(가장 드리프트 위험이 큰 부분)는 jest 라 항상 돈다.

## 6. 배포 순서와 선행조건

`core → admin-web → 스킬 zip 배포` 순서다. 가드 없이 스킬이 먼저 돌면 보호막 없이 사고가 날 수 있다.

**마이그레이션 0건 · 시크릿 0건 · env 0건 · 이벤트 계약 0건.**

⚠️ **선행조건 — 이 스펙과 별개로 이미 열려 있는 것들**:

- 라이브 core 가 `9331f7a88`(업로드 엔드포인트를 Fastify multipart 직접 파싱으로 교체) 이전일 가능성이 높다. **그러면 양식 업로드 자체가 동작하지 않는다.** 이 스펙의 어떤 것도 그 위에서는 검증할 수 없다
- 수동 스모크 53항목이 한 건도 실행되지 않았다
- MD 계정의 `roles` 가 실측되지 않았다 — `master`/`admin` 이 없으면 화면이 열리지 않는다

## 7. 졸업 경로 (지금 하지 않음)

원격 MCP 커넥터로 올리면 AI 가 양식 다운로드·업로드·오류 조회를 직접 하므로 「오류 목록 복사」가 필요 없어지고, **커넥터는 관리자가 조직 단위로 관리할 수 있어 §3.10 의 배포 문제도 함께 풀린다.**

대신 서버 구축·호스팅·OAuth 가 붙는다. 스킬에 쌓은 도메인 지식과 스크립트는 그대로 재사용되므로, 스킬로 먼저 검증하고 MD 가 실제로 쓴다는 것이 확인되면 그때 올린다.

## 8. 런타임 실측 결과 (2026-08-05, Claude Desktop)

| 항목 | 결과 | 영향 |
|---|---|---|
| openpyxl | **사전 설치됨 (3.1.5)** | 스크립트 기반 설계(§3.3·§3.4) 성립 |
| 외부 네트워크 | **프록시가 403 으로 차단** | §3.7 의 대비책이 **기본 경로**가 된다 |

네트워크 결과의 의미를 정확히 적어둔다. 차단은 프록시 정책이고 테스트는 한 도메인(`google.com`)으로만 했으므로 "전면 차단"이 증명된 것은 아니다. 하지만 크롤링 시나리오의 이미지 URL 은 임의 쇼핑몰 도메인이라 **허용 목록에 있을 이유가 없다.** 따라서 설계는 "AI 가 직접 못 내려받는다"를 전제로 굳힌다.

**바뀌는 것은 절차 한 단계뿐이다.** AI 는 이미지 시트에 최종 파일명을 미리 적고, 그 파일들을 받는 다운로드 스크립트와 매니페스트를 만들어 MD 에게 준다. MD 가 로컬에서 그것을 실행한 뒤 admin-web 3단계에서 폴더를 끌어다 놓는다. 워크북은 다운로드 성공 여부와 무관하게 완성된 상태로 나가므로 §3.3·§3.4 는 영향받지 않는다.

**§3.5 규칙 8 이 더 중요해진다** — AI 가 이미지를 확보할 수단이 없으니, 무엇이 빠졌는지 경고·목록·조치 방법을 말하는 것이 유일한 안전장치다.
