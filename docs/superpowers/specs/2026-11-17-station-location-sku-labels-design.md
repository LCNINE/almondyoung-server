# 스테이션 로케이션·SKU 라벨 출력 설계 (#1281)

상위: #1233 (셀메이트 컷오버 1단계) · 파생: #1356 (셀메이트 `바코드번호2` 누락)

## 1. 왜

창고는 로케이션 자석 라벨과 SKU 바코드 스티커를 셀메이트에서 뽑는다. 1단계 T 다음 날부터 자사몰 주문의 피킹·검수와 입고를 warehouse-app(Windows 스테이션)으로 한다. 그때부터 스캔은 core 데이터에 기댄다.

1단계에도 셀메이트는 마켓 주문 때문에 살아 있다. 그래도 아래 두 경우는 셀메이트로 해결되지 않는다.

- core 에만 있는 것: T 뒤 core 에서 만든 SKU, `PUT …/racks/:rackId` 로 끝 번호를 늘려 생긴 칸.
- 고쳐 읽은 칸(`CC-4-1` → `CC-04-01`)은 셀메이트 텍스트와 꼴이 달라서 자석을 새로 붙여야 한다.

**목표:** 스테이션에서 BIXOLON SLP-TX400 으로 로케이션 라벨과 SKU 라벨을 실제 크기로 뽑는다. 뽑은 라벨은 스캔하면 적치 목적지와 SKU 로 잡혀야 한다. 송장 프린터(Xprinter XP-DT108B)의 설정과 출력은 지금처럼 동작해야 한다.

## 2. 범위

**목표**
- 송장 프린터와 따로 «라벨 프린터» 설정 칸을 둔다. 테스트 인쇄도 칸별로 한다.
- 로케이션 라벨(3×5 cm)을 코드 하나·랙 하나·고른 여러 칸 단위로 뽑는다.
- SKU 라벨을 1×3 cm 와 3×5 cm 중에서 골라 원하는 장수만큼 뽑는다.

**비목표**
- 중국 쪽 출력. 중국 직원의 업무 환경(PC·프린터)을 물류팀장에게 묻는 중이다(2026-11-17). 그쪽 출력이 필요해지면 이 문서의 core 엔드포인트를 그대로 부르게 한다.
- admin-web 에서 출력하는 것.
- 입고 검수 화면 안에서 바로 뽑는 것. 원칙적으로 바코드 없이 창고에 들어오는 상품은 없다(사용자).
- 한글이 든 로케이션 코드의 바코드화. 아래 §6 참고.
- `바코드번호2` 누락 수정(#1356).

**반목표: 기술적으로 동작해도 실패로 보는 것**
- 송장 출력이 한 번이라도 라벨 프린터로 가는 것, 또는 그 반대.
- 스티커는 나왔는데 리더기가 못 읽는 것. 특히 1×3 cm.
- 라벨의 바코드 값과 스캔 해석(`resolveSkuIdByBarcode`, 적치 화면의 `locations.code` 일치)이 어긋나는 것.

## 3. 현장 사실

**SKU 스티커(셀메이트 실물 사진, 2026-11-17)**
- **1×3 cm:** 위에 바코드, 아래에 상품명 최대 두 줄. 사람이 읽는 숫자는 없다.
- **3×5 cm:** 위에 상품명, 아래에 바코드와 그 아래 숫자.
- **바코드 값은 `sku_barcodes` 의 대표 바코드다.** 예: `11198120000` = «캐릭터 땅콩 브러쉬»의 `is_primary` 행. 거의 전부 셀메이트 11자리 코드이고, SKU 코드(`32167` 꼴)는 바코드로 쓰이지 않는다.
- **1×3 의 바코드는 조밀하고 양옆 여백이 거의 없다.** 그래도 리더기는 읽었다(사용자). 사진 비율로 재면 바코드 폭은 1×3 이 약 27 mm, 3×5 가 약 39 mm 다.

**바코드 데이터(라이브 core, 2026-11-17)**
- 대부분의 SKU 에 대표 바코드가 있다.
- 쓸 수 있는 바코드가 없는 SKU 가 조금 있다. 대부분 셀메이트 동기화로 들어온 것이다.
- 엑셀 수식 꼴(`="…"`) 행은 이제 0이다. `scripts/sellmate/clean-formula-barcodes.ts` 가 정리했다.
- 대표 바코드가 둘인 SKU 는 0이다.
- 깨끗한 바코드 중 가장 긴 값은 35자다.
- 숫자는 다시 잰다. 재는 법은 §8 에 있다.

**core 에서 만든 SKU:** 대표 바코드가 SKU 코드와 같은 값으로 자동으로 생긴다(`sku-catalog.manager.ts`). 따라서 바코드를 따로 발급할 곳은 필요 없다.

**로케이션**
- 칸 코드는 `열-랙-칸` 꼴이다(`location-code.ts`, `shelf-code-reading.ts`).
- 커스텀 칸은 한글을 그대로 쓴다(`M-07-꼭대기`). 라이브에는 3칸이 있고, 모두 재고 0이다.
- 셀메이트는 자유 텍스트 로케이션도 1D 바코드로 찍었다(QR 아님, 사용자 확인). 무엇을 실었는지는 모른다. 다만 2026-11-18 현장에서 본 한글 칸 둘에는 바코드가 아예 없었다(§6).

**프린터**
- **TX400:** 203 dpi(8 dot/mm), 최대 인쇄 폭 108 mm. 에뮬레이션은 SLCS·BPL-Z(ZPL II 호환)·BPL-E 를 지원한다.
- **TX400 은 한 대다.** 롤을 갈아 끼워 1×3 과 3×5 를 모두 뽑는다(사용자). 롤은 한 줄에 스티커 한 장이 이어진 한 줄짜리다. 1×3 롤의 폭은 3 cm 다.
- **로케이션 라벨은 SKU 3×5 와 같은 라벨지를 쓴다.**
- **셀메이트는 1단계 동안 이 TX400 으로 계속 출력한다.** 에뮬레이션을 따로 바꾼 적이 없고, 기기에 스위치도 없다(사용자). 그런데도 다른 출력이 «둘 다 잘 나왔다». 따라서 **우리 쪽에서 에뮬레이션 설정을 바꾸지 않는다.** ZPL 을 지금 설정 그대로 받아들이는지는 실물로 확인한다(§7).
- **송장 프린터 XP-DT108B:** ZPL 을 알아듣는다(#913 실물 확인).

## 4. 접근

| 안 | 내용 | 대가 |
|---|---|---|
| **A (채택)** | core 가 라벨 바이트(ZPL)를 만들고, 앱은 그대로 프린터로 보낸다. 송장 렌더러를 다시 쓴다. | core 를 먼저 배포하고 앱을 배포해야 한다. 렌더러 공통부를 옮겨야 한다. |
| B | 앱이 ZPL 을 만든다. | 한글을 찍으려면 TX400 ZPL 모드의 한글 글꼴(미확인)에 기대거나, 앱에 래스터라이저를 하나 더 만들어야 한다. 렌더러가 두 벌이 된다. 중국 출력 때 다시 만들어야 한다. |
| C | 로케이션은 앱이, SKU 는 core 가 만든다. | 길이 둘이 되는데 얻는 게 없다. |

**사용자는 A 를 골랐다(«하던 대로»).** 송장(#913)과 같은 길이다. 한글은 나눔고딕 비트맵(`^GF`)으로 찍고, 바코드는 프린터 명령(`^BC`)으로 그린다.

## 5. 설계

### 5-1. core: 렌더러 공통부를 옮긴다

`fulfillment/waybill/label/` 에서 캐리어와 상관없는 파일을 `apps/core/src/platform/label/` 로 옮긴다. 대상은 `label-model`, `svg-rasterizer`, `svg-text`, `zpl-encoder`, `label-document` 와 각자의 spec 이다. **(Claude 판단)** `platform` 은 auth·database 처럼 여러 도메인이 함께 쓰는 기반이 있는 자리다.

- **동작은 바꾸지 않는다.** 송장 spec 이 그대로 초록이어야 한다.
- 이 파일들을 import 하는 곳도 함께 고친다. `scripts/ops/hanjin-label-preview/render.ts` 와 `label/__support__/label-invariants.ts` 가 있다.
- `SvgRasterizer` provider 는 공용 모듈 하나가 내보낸다. 송장 모듈과 라벨 모듈이 그 모듈을 import 한다. Nest 11 에서는 같은 동적 모듈을 두 번 등록하면 두 벌이 생기므로, 정적 모듈로 둔다.
- 인코더 확장은 두 가지다.
  - **장수:** `encodeZpl` 의 `^PQ1` 을 옵션으로 받는다(`copies`, 기본 1). 장수만큼 쪽을 반복하지 않고 `^PQn` 으로 찍는다. 바이트가 작다.
  - **Code128 자동 부호 집합:** 숫자 쌍을 subset C 로 줄여야 11자리가 1×3 에 들어간다. `^BC…,A`(자동 모드)를 쓰거나, 인코더가 `>;`·`>6` 같은 부호 전환을 직접 넣는다. 둘 중 무엇이 TX400 에서 동작하는지는 실물로 정한다(§7). 폭 계산(`barcodeWidthMm`)은 실제로 쓰는 부호화에 맞춘다. 지금은 subset B 상한이다.

### 5-2. core: 라벨 엔드포인트

위치는 `apps/core/src/modules/inventory/labels/` 다. 레이어는 Controller → Service → Reader(데이터)와 렌더러(순수 함수) 순서로 둔다.

**권한:** `@RequirePermission('inventory.stock.read')`. 라벨을 그리는 일은 읽기이고 상태를 바꾸지 않는다. 새 권한 키는 만들지 않는다. 몸체로 목록을 받아야 해서 POST 를 쓴다.

**`POST …/labels/locations`**
- 몸체: `{ rackId }` 와 `{ locationIds: string[] }` 중 정확히 하나.
- `rackId` 를 주면 그 랙의 활성 칸 전부를 코드 순서로 그린다.
- 시스템 로케이션은 제외한다.

**`POST …/labels/skus`**
- 몸체: `{ size: '30x10' | '50x30', items: [{ skuId, copies }] }`.

**응답(둘 다):** `{ format: 'zpl', data, labels, skipped: [{ ref, code, reason }] }`
- `data` 는 쪽마다 `^XA…^XZ` 를 이어 붙인 문자열이다. 앱은 송장처럼 통째로 `print_raw` 한다.
- `skipped` 는 그리지 못한 항목과 사유다.
  - `UNSUPPORTED_CODE`: 로케이션 코드에 ASCII 출력 가능 문자 밖의 글자가 있다.
  - `NO_BARCODE`: SKU 에 쓸 수 있는 바코드가 없다.
  - `BARCODE_TOO_WIDE`: 1 dot 모듈로도 라벨 폭에 안 들어간다. 사유 문구로 3×5 를 쓰라고 안내한다.
- 그릴 게 하나도 없으면 `data` 는 빈 문자열이고 `skipped` 만 채운다. 에러로 던지지 않는다.

**상한 (Claude 판단)**
- 한 요청의 라벨 수는 500장(장수 포함)까지다.
- 항목 하나의 `copies` 는 1~200 이다.
- 넘으면 400 이다. 랙 하나는 수십 칸이라 걸리지 않는다.

**SKU 바코드 고르기**
1. `is_primary` 행을 쓴다.
2. 대표가 없으면 `created_at` 이 가장 이른 행을 쓴다.
3. 행이 없으면 `NO_BARCODE` 로 건너뛴다.

**고른 값은 스캔 두 길로 모두 같은 SKU 에 돌아와야 한다.** spec 이 두 왕복을 다 지킨다.
- core 출고 흐름(검수·단순출고·반품): `resolveSkuIdByBarcode`.
- 앱의 입고·적치 스캔: `GET /inventory/skus?barcode=`. 이 길은 `sku_barcodes` 정확 일치만 보고 `skus.code` 로 대신 찾지 않는다. 그래서 `sku_barcodes` 행이 없는 SKU 는 입고에서 안 잡힌다(§5-7 이 메운다).

**로케이션 바코드 값은 `locations.code` 그대로다.** core 에 있는 `barcode.service.ts` 의 `generateLocationBarcode`(`LOC-` 접두어)는 적치 화면이 읽지 않으므로 쓰지 않는다.

**상품명:** `skus.name` 을 그대로 쓴다. 셀메이트 스티커에 `[단일상품]` 이 없으므로 송장용 `labelSkuNameOf` 는 쓰지 않는다.

### 5-3. 라벨 템플릿

모든 템플릿은 가로 방향 mm 로 그린다. 넣는 방향(`rotation`)은 §7 의 실물 출력으로 정한다. 셋 다 108 mm 안에 들어간다. 바코드는 Code128 이고 높이·위치는 아래를 따른다. 모듈 폭은 «기준 모듈»에서 시작하고, 라벨 폭에서 좌우 1 mm 를 뺀 폭을 넘으면 1 dot 씩 줄인다. **2 dot 가 바닥이다.** 2 dot 로도 넘으면 `BARCODE_TOO_WIDE` 다. **(Claude 판단)** 리더기가 읽는다고 확인된 가장 조밀한 값이 셀메이트 1×3 의 2 dot 다. 1 dot(0.125 mm)는 확인된 적이 없다.

| 라벨 | 크기(가로×세로) | 배치 | 기준 모듈 |
|---|---|---|---|
| 로케이션 | 50×30 mm | 위 절반: 코드 글자를 크게(칸 폭에 맞춰 `fitSizePt`). 아래: 바코드(값 = `locations.code`). | 3 dot |
| SKU 소 | 30×10 mm | 위: 바코드(높이 약 5 mm). 아래: 상품명 최대 두 줄, 넘치면 말줄임. 숫자 없음. | 2 dot |
| SKU 대 | 50×30 mm | 위: 상품명 최대 두 줄. 아래: 바코드와 그 아래 숫자. 숫자는 SVG 글자로 그린다(프린터 글꼴을 쓰지 않는다). | 3 dot |

- 11자리 셀메이트 코드를 subset C 로 부호화하면 약 112 모듈이다. 2 dot 면 28 mm 로 1×3 에 들어간다. 대신 quiet zone 은 거의 없다. 셀메이트 실물이 그랬고 리더기가 읽었다(§3).
- 로케이션 라벨의 모양은 셀메이트 자석 사진을 보지 못하고 정했다. **(Claude 판단)** 사람이 멀리서 읽는 코드 글자를 크게, 바코드를 아래에 둔다.

### 5-4. 앱: 프린터 칸 둘

- **송장 프린터:** 기존 키 `almondwms.labelPrinter` 를 그대로 둔다. 창고 PC 의 설정이 살아 있어야 하기 때문이다. 바뀌는 건 화면의 이름(«송장 프린터»)과 설명뿐이다. 송장 출력 코드는 계속 이 키를 읽는다.
- **라벨 프린터:** 칸은 하나다. 한 대에서 롤만 갈아 끼우기 때문이다. 새 키를 둔다(예: `almondwms.barcodeLabelPrinter`). 입력 규칙(`spooler://` 와 `tcp://`)은 송장 칸과 같으므로 함수를 키로 매개화한다.
- **설정 화면(`SettingsRoute`):** 두 절을 둔다. 각 절에 저장과 테스트 인쇄가 있다. 라벨 칸의 테스트 라벨은 50×30 기준으로 그려 크기가 맞는지 보이게 한다.
- **진단 화면(`DiagnosticsScreen`):** 테스트 인쇄를 칸별로 한다. 지금은 대상을 입력창으로 따로 받는데, 저장된 칸 값을 읽어 보내게 바꾼다.
- **인쇄 상태(`printerStatus`):** 지금은 한 벌이다. 칸별로 나눠서, 한쪽 실패가 다른 쪽 표시를 덮지 않게 한다.
- **안내 문구:** 라벨 프린터가 비었을 때 «송장 프린터»라는 말이 나오지 않아야 한다.

### 5-5. 앱: SKU 라벨

- SKU 상세 화면(`/inventory/$sku`)에 «라벨 출력»을 둔다.
- 고르는 것은 크기(1×3 / 3×5)와 장수(기본 1)다. 마지막으로 고른 크기는 기기 설정에 기억한다.
- 인쇄 전에 찍힐 바코드 값을 보여 준다.
- `NO_BARCODE` 나 `BARCODE_TOO_WIDE` 면 사유를 보여 주고 아무것도 보내지 않는다.

### 5-6. 앱: 로케이션 라벨 화면

- 새 경로(예: `/labels/locations`)를 만들고, 스테이션 메뉴에서 들어간다.
- 창고는 `WarehousePicker` 로 고른다.
- 고르는 방법은 두 가지다.
  - **랙:** `GET …/warehouses/:id/racks` 목록에서 랙을 고르고 «랙 전체 출력»을 누른다.
  - **칸:** `useLocationSearch` 로 코드를 찾아 목록에 담고(스캔 또는 입력) «담은 칸 출력»을 누른다. 코드 하나만 뽑는 것도 이 길이다.
- 보낸 장수와 `skipped` 를 결과로 보여 준다. 한글 칸은 «이 칸은 아직 라벨을 뽑을 수 없어요»로 보인다.

### 5-7. 데이터 정리 (일회성)

`sku_barcodes` 행이 하나도 없는 SKU 에 SKU 코드를 대표 바코드로 등록한다. core 에서 만든 SKU 와 같은 규칙이다. 이 SKU 들은 셀메이트에도 바코드가 비어 있었다. 그러니 붙어 있는 스티커가 없을 것으로 보고, 재고가 있는 것은 T 전에 새 라벨을 붙인다.

**스크립트 규칙**
- 형태는 `scripts/sellmate/*` 와 같은 멱등 스크립트다. dry-run 을 먼저 돌린다.
- 이미 그 값을 다른 SKU 가 쓰고 있으면 충돌로 보고만 하고 넣지 않는다.

**순서:** #1356 의 백필보다 **뒤에** 돌린다. 백필이 제조사 바코드를 채우는 SKU 가 생길 수 있기 때문이다.

## 6. 한글 로케이션 코드

- 이번 범위에서는 바코드로 만들지 않고 `UNSUPPORTED_CODE` 로 건너뛴다.
- ~~셀메이트가 1D 바코드에 무엇을 실었는지 현장에서 확인한다.~~ **2026-11-18 부천 확인: 본 한글 칸(`G-04-바닥`·`Z-03-맨위`)에는 자석도 바코드도 없었다.** 부피가 크거나 무거운 상품 자리는 셀메이트에 글자로만 적고 바코드를 뽑지 않은 것으로 보인다. 따라 할 셀메이트 방식이 없다.
- 남은 둘 중 하나로 정한다. 어느 쪽이든 후속 이슈다.
  - 영문 코드로 바꾼다. **(Claude 제안)** 코드는 영문(예: `G-04-B1`)으로 두어 라벨을 뽑고, «바닥» 같은 한글은 표시 이름에 남긴다 — 로케이션 검색이 코드와 표시 이름을 함께 찾으므로 사람은 계속 한글로 찾는다.
  - 커스텀 칸 이름을 ASCII 로 제한한다.
- 그 전까지도 칸은 쓸 수 있다. 적치 대상 칸에 코드 일부를 치면 후보로 뜬다. 막히는 건 스캔만 받는 화면뿐이다(예: 원위치가 여럿인 반품 되돌리기).

## 7. 검증

**자동(PR 게이트)**
- 렌더러 spec:
  - 크기별로 `^PW`/`^LL` 이 라벨 크기와 맞는다.
  - 바코드가 라벨 폭 안에 들어간다.
  - 모듈을 줄이는 규칙과 `BARCODE_TOO_WIDE` 가 맞게 동작한다.
  - 한글 이름이 두 줄 안에서 말줄임된다.
  - `^PQn` 이 장수와 맞는다.
- SKU 바코드 고르기 spec: 대표 있음, 대표 없음, 바코드 없음. 고른 값이 `resolveSkuIdByBarcode` 와 `GET /inventory/skus?barcode=` 두 길 모두로 같은 SKU 에 돌아오는지도 본다.
- 로케이션 spec: 랙 전체가 활성 칸만 코드 순서로 나온다. 시스템 로케이션은 빠진다. 한글 코드는 건너뛴다.
- 송장 spec 은 렌더러를 옮긴 뒤에도 그대로 초록이어야 한다.
- 앱 spec:
  - 두 프린터 키가 섞이지 않는다. 송장은 송장 키로만, 라벨은 라벨 키로만 간다.
  - 기존 `almondwms.labelPrinter` 값이 송장 칸으로 그대로 보인다.
  - 칸별 테스트 인쇄와 상태 표시가 따로 동작한다.
- 로컬 스모크: 역렌더 이미지에서 바코드를 디코드해 값이 맞는지 본다. 방법은 #913 과 같다(`zpl-renderer-js` 역렌더 + `zxing-cpp` 디코드). 일회성 도구라 저장소에 넣지 않는다.

**실물(사용자와 함께, 머지 전)**
1. TX400 설정을 건드리지 않은 채 ZPL 테스트 라벨이 나오는지 본다. 그 뒤 셀메이트 스티커도 그대로 나오는지 본다. ZPL 이 안 먹으면 여기서 멈추고, 셀메이트 출력을 깨지 않을 방법을 따로 정한다.
2. Code128 자동 부호 집합(§5-1)이 TX400 에서 동작하는지 본다. 11자리 바코드가 subset C 폭(1×3 에서 약 28 mm)으로 나와야 한다.
3. 1×3 과 3×5 SKU 라벨을 창고 리더기로 스캔해 SKU 가 잡히는지 본다.
4. 로케이션 라벨을 적치 화면에서 스캔해 목적지로 잡히는지 본다.
5. 같은 PC 에서 송장이 Xprinter 로 그대로 나오는지 본다.

**라벨지를 바꿀 때:** 롤을 바꾸면 TX400 갭 센서를 보정해야 할 수 있다. 런북 한 줄로 남긴다.

**넣는 방향:** 1×3 은 30 mm 가 롤 폭이라 `rotation: 0` 이다. 3×5 롤이 50 mm 와 30 mm 중 어느 쪽이 폭인지는 첫 출력에서 정한다. 30 mm 쪽이 폭이면 90° 또는 270° 다(송장 때처럼 실물로 고른다).

## 8. 재는 법

라이브 터널을 띄운 뒤 `deployments/lcnine/services` 에서 아래를 실행한다.

```
npx sst shell --stage live -- node <스크립트>
```

스크립트는 core DB 를 읽기 전용으로 조회한다.

- 바코드가 없는 SKU: `sku_barcodes` 행이 없는 SKU.
- 수식 꼴 행: `barcode ~ '^="'` (0이어야 한다).
- 한글 로케이션 코드: `locations.code ~ '[^\x20-\x7E]'`.
- 가장 긴 바코드: `max(length(barcode))`.

## 9. 배포

- 마이그레이션은 없다.
- **core 를 먼저 배포하고 앱을 배포한다.** 앱 새 화면은 core 의 새 엔드포인트를 부른다.
- 데이터 정리 스크립트(§5-7)는 core 배포와 상관없이, #1356 백필 뒤에 돌린다.

## 10. 빌더에게 맡기는 것

- 경로 접두어(`/inventory/labels/…` 와 기존 컨트롤러 규칙 중 어느 쪽에 맞출지), DTO 이름, 라벨 프린터 prefs 키 이름.
- 템플릿 안의 정확한 글자 크기와 여백. 위 표의 배치와 기준 모듈을 지키는 범위에서 정한다.
- 로케이션 화면이 스테이션 메뉴의 어느 자리에 들어갈지. 단축키가 겹치지 않게 한다(#1255 선례).
