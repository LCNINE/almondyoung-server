# 함께 배송(Add to Delivery) 설계

출고 전 주문에 상품을 더 사면 배송비 없이 같은 상자로 보낸다. 택배·WMS 연동이 끝나기 전(셀메이트 시기)부터 쓰고, WMS 로 넘어가도 같은 판정으로 이어진다.

시안: 모바일·태블릿·PC 마이페이지 세 상태(평소, 부모 취소 확인, 부모만 취소한 뒤). 링크는 채팅에만 둔다.

## 용어

- **부모 주문**: 함께 받을 대상이 되는 출고 전 자사몰 주문.
- **추가 주문**: 부모에 붙여 결제한 별개의 주문. 주문을 합치지 않는다.
- **면제 배송비**: 추가 주문이 혼자 나갔다면 냈을 배송비(제주·도서 추가비 포함). 추가 주문 결제 때 한 번 계산해 남긴다.

## 결정

### 진입과 결제

1. 상품 상세에 버튼을 둔다. 누르면 그 상품만 담긴 짧은 체크아웃으로 간다. 배송지는 부모 것으로 잠기고 배송비는 0원으로 보인다. 결제수단은 고객이 고른다.
2. 부모 후보는 출고 전 주문의 배송지로 정한다(Medusa 기본 배송지가 아니다). 배송지가 하나면 그 배송지의 가장 최근 주문을 자동으로 고르고, 여럿이면 고객이 고른다.
3. 부모 후보에서 뺀다: 채널 주문(네이버·쿠팡), 디지털만 든 주문, `selfCancelBlock` 에 걸린 주문, 결제가 끝나지 않은 주문(입금 대기).
4. 버튼은 부모 상품과 같은 배송비 그룹 상품에만 뜬다(현재는 부천·셀메이트 그룹. 인쇄·직배송·디지털은 뜨지 않는다). 기본 배송비와 제주·도서 추가비를 모두 면제한다.
5. 추가 주문 체크아웃은 즉시 결제수단만 보인다(카드·간편결제·포인트). 가상계좌·무통장은 숨긴다. 입금 대기 주문은 수집에서 빠져서, 그사이 부모가 먼저 나가기 때문이다.
6. 결제 순간에 다시 판정한다. 부모가 이미 출고됐거나 후보에서 빠졌으면 `complete-cart` 검증 훅에서 막는다. 지연 승인이라 PG 승인 전이므로 돈이 빠져나가지 않는다. 문구: "함께 받을 주문이 방금 출고됐어요. 배송비를 포함해 다시 결제해 주세요." 같은 장바구니를 일반 주문으로 바꾸는 버튼을 준다.
7. 되돌리기 버튼은 따로 두지 않는다. 추가 주문도 출고 전에는 기존 주문 취소로 바로 취소된다. 저장 카드 원탭을 붙일 때 다시 본다.

### 취소와 환불

8. 부모를 전체 취소하려 하면 확인 창을 띄운다. [같이 취소하기 · 전액 환불] / [이 주문만 취소하기] / [닫기].
9. 부모만 전체 취소하면 추가 주문의 면제 배송비를 부모 환불에서 뺀다. 뺄 금액은 부모 환불액을 넘지 않는다.
10. 부모를 취소한 뒤 추가 주문까지 취소하면 아무것도 나가지 않으므로, 뺐던 배송비를 돌려준다.
11. 부모 부분 취소는 상관없다. 부모 상품이 하나라도 남으면 같이 나간다.
12. 취소 이유 모달:
    - "상품을 더 담고 싶어요" → 취소하지 않는다. "이 주문에 함께 받을 상품을 고르세요"로 상품 목록에 보낸다.
    - "옵션이나 수량을 바꾸고 싶어요" → 취소를 진행하고 완료 화면에 "같은 상품 다시 담기"를 붙인다.
    - 나머지 → `reasonCode` 만 남기고 바로 취소한다.

### 화면

13. 마이페이지는 부모 카드 안에 "함께 배송" 영역을 두고 추가 주문을 그 아래에 넣는다. 배송 조회 버튼은 하나, 취소는 주문마다.

| 상황 | 추가 주문 쪽 문구 |
|---|---|
| 평소 | "위 주문과 함께 배송돼요." / "배송비 3,000원이 면제됐어요." |
| 부모만 취소 | 혼자 카드가 된다. "함께 받을 주문이 취소돼서 따로 배송돼요." / "배송비 3,000원은 취소한 주문의 환불에서 뺐어요." |
| 부모 환불 내역 | "함께 받을 주문 배송비 −3,000원" |

### 구조

14. 판정은 Medusa 함수 하나에 둔다. Medusa 가 고객의 후보 주문(취소·입금 대기 아님, 같은 배송비 그룹)을 고르고, Core 내부 라우트(`/internal/sales-orders/…`, `CORE_INTERNAL_KEY`)에 "이 중 고객이 아직 직접 취소할 수 있는 주문"을 묻는다. Core 에 있는 주문은 결제가 끝난 주문이다(입금 대기는 수집 단계에서 빠진다). 세 곳이 이 함수를 쓴다.
    - 상품 상세 버튼: Medusa store 라우트
    - 0원 배송비: `AlmondFulfillmentProviderService.calculatePrice` (카트 `context.id` 로 metadata 의 부모 id 를 읽는다)
    - 결제 재판정: 기존 `complete-cart.ts` 검증 핸들러 안에 함수를 더한다(새 훅 등록 금지)
15. Core 의 출고 전 판정은 `selfCancelBlock` 을 그대로 쓴다. 셀메이트 시기엔 shipped 전, WMS 시기엔 피킹 시작 전으로 자동으로 바뀐다.
16. 카트 metadata 에 부모 주문 id(`add_to_delivery_parent_order_id`)를 넣고, 완료 때 주문 metadata 로 그대로 옮겨진다. 면제 배송비는 따로 저장하지 않는다. 추가 주문의 배송 방식에 남는 결제 시점 정책(`policySnapshot`)과 그 주문의 상품·우편번호로 다시 계산한다. 정책이 나중에 바뀌어도 결제 때 값이 나온다.
17. 자사몰 주문 환불은 Medusa 가 한다(`channel-cancel-order.ts`). Medusa 기본 전체취소는 마지막에 남은 결제액을 전부 환불하고, Core 는 다시 수집한 `OrderCancelled` 로 취소를 확정하므로 부모는 Medusa 에서도 취소돼야 한다. 그래서:
    - 부모만 전체취소(고객 부담 사유일 때만, 부분취소와 같은 `cancelShippingFeeBearer`)는 남은 결제액에서 살아 있는 추가 주문들의 면제 배송비 합을 빼고 환불한 뒤, 그 금액을 metadata `add_to_delivery_hold` 에 적고, 기본 취소에서 남은 금액 환불만 뺀 워크플로로 취소한다.
    - 추가 주문이 전체취소되면(자기 환불 뒤·자기 취소 전) 부모 잠금을 잡고 보류에서 이제 필요 없는 몫을 결제 모듈로 바로 돌려준다(취소된 주문엔 refundPaymentWorkflow 를 쓸 수 없다). 자식마다 한 번.
    - 추가 주문은 전체취소를 시작할 때 `add_to_delivery_canceling_at` 를 먼저 적어, 겹쳐 들어온 부모 취소가 그 몫을 보류하지 않게 한다.
    - 같이 취소는 두 요청이 어떤 순서로 처리돼도 부모가 결국 전액을 돌려받는다.
18. Core 는 셀메이트 시기에 부모 연결을 몰라도 된다. Core 스키마·이벤트 계약 변경은 WMS 자동 합포장을 만들 때 한다.

### 운영

19. 셀메이트 시기: 추가 주문은 부모의 수령자·주소를 그대로 복사하므로 셀메이트 묶음정리(전체사이트, 수령자+주소, 7일, 한번만 묶음정리 꺼짐)가 묶는다. 수집 스크립트의 묶음 로직은 바꾸지 않는다.
20. 런북: shipped 직전과 직후에 "이번 회차 부모에 연결된 추가 주문 중 결제는 끝났는데 이번 수집 파일에 없는 것"을 찾는다. 찾으면 같은 회차에서 추가 업로드하고 함께 shipped 로 바꾼다. 송장이 이미 출력돼 따로 나간 건수는 회차 보고에 한 줄 남긴다.
21. WMS 시기: 추가 주문의 상자를 만드는 흐름 안에서 부모 상자와 자동 합포장한다(기존 `POST consolidations` 로직, 시스템 요청자). 크론은 없다. 실패하면 합포장 보드 후보로 남는다(같은 고객·주소라 이미 후보로 뜬다). 이 항목은 WMS 전환 때 만든다.

## 하지 않는 것

- 주문 합치기. 추가 주문은 끝까지 별개 주문이다.
- 채널 주문(네이버·쿠팡)에 붙이기.
- 원탭 결제와 되돌리기.
- 셀메이트 시기의 WMS 자동 합포장.

## 남은 위험

- 수집 파일을 뽑은 뒤 송장 출력까지 사이에 결제된 추가 주문은 런북이 잡는다. 송장 출력 뒤면 따로 나가고 배송비는 우리가 낸다.
- 부모 취소 환불 차감이 악용되는지(싼 상품만 0원 배송으로 받기)는 회차 보고의 따로 배송 건수로 본다.
