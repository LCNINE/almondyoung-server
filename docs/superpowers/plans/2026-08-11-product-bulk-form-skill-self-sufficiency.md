# product-bulk-form 스킬 자립화 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** MD 가 `skills/product-bulk-form` 스킬만으로 양식 작업과 트러블슈팅을 끝낼 수 있게 한다 — 막혔을 때 개발자를 부르지 않아도 되는 지점까지.

**Architecture:** 문서만 바꾼다. `references/troubleshooting.md` 를 새로 만들어 "막혔을 때"의 진입점을 세우고(증상 문진 → 오류 역인덱스 → phase 교착), 낡은 `workflow.md` §1 을 현행 UX 로 교체하고, `semantics.md` 에 빠진 지식 둘을 넣는다. `SKILL.md` 는 진입 규칙 한 줄과 버전만 바뀐다.

**Tech Stack:** Markdown. 검증은 `python3 -m pytest`(기존 30건 회귀 감시)와 `npm run build:bulk-form-skill`(zip 빌드), 그리고 사람이 밟는 드라이런.

## Global Constraints

- **코드 변경 0건.** `apps/core`·`apps/admin-web` 를 수정하지 않는다. 마이그레이션 0 · 시크릿 0 · env 0 · 이벤트 계약 0
- **손대지 않는 파일:** `references/columns.md`(자동 생성물, 2026-08-11 대조에서 drift 0) · `references/recipes.md` · `scripts/` · `tests/` · `requirements-dev.txt`
- **모든 문서는 한국어.** 기존 4개 문서의 문체(평서형 종결, `**볼드**` 로 규칙 강조, 표 우선)를 따른다
- **인용 문구는 코드 원문 그대로 옮긴다.** 값이 끼어드는 자리는 `…` 로 줄인다. 문구를 지어내지 않는다 — 이번 작업의 발단이 존재하지 않는 안내 문구였다
- **파일 경로 접두:** 모든 대상 파일은 `skills/product-bulk-form/` 아래에 있다
- **SKILL.md 버전은 최종 태스크에서 한 번만 올린다** (1.0.0 → 1.1.0). 중간 태스크에서 건드리지 않는다 — zip 파일명이 버전에서 나오므로 중간 값이 배포물로 새면 안 된다

### 2.1 행 오류 — 그 행만 떨어진다

검토 화면의 **「오류」 탭**에 뜬다. 헤더의 **「오류 목록 복사」** 버튼으로 전문을 받아
붙여넣게 하면 한 번에 여러 건을 다룰 수 있다.

**이 행들은 승인해도 진행되지 않는다** — 승인 창이 "오류 N건은 제외하고 M건을 진행합니다"
라고 알려 준다. 살리려면 **양식을 고쳐 새 세션으로 다시 올려야** 한다. 옛 세션은 「세션
취소」로 정리한다.

**구조 — 프리필(수정) 행은 옵션·조합을 못 바꾼다**

| 문구 | 원인 | 조치 |
|---|---|---|
| `옵션값을 추가할 수 없습니다: …` | 프리필 행의 옵션 시트에 없던 옵션값키를 새로 적었다 | 그 행을 원래대로 되돌린다. 옵션값 추가는 **상품 상세 화면**에서만 된다 |
| `옵션값을 삭제할 수 없습니다: …` | 프리필 행의 옵션 시트 행을 지웠다 | 지운 행을 되살린다. 상품 시트에 남긴 상품은 옵션·조합 행도 전부 남겨야 한다 |
| `조합 행을 지울 수 없습니다: …` | 프리필 행의 조합 시트 행을 지웠다 | 같음 |
| `없던 조합을 만들 수 없습니다: …` | 프리필 행에 새 조합을 더했다 | 같음 |
| `같은 옵션키에 서로 다른 옵션명이 적혀 있습니다: …` | 한 옵션키의 옵션명 칸이 행마다 다르다 | 같은 옵션키의 옵션명을 한 값으로 통일한다 |
| `옵션값키가 여러 옵션 그룹에 걸쳐 있습니다: …` | 신규 행에서 한 옵션값키를 두 옵션 그룹에 썼다 | 옵션값키는 그룹마다 다르게 짓는다 |
| `한 옵션 그룹 안에서 옵션값 표시명이 중복되었습니다: …` | 신규 행의 한 그룹에 같은 이름의 옵션값이 둘 | 이름을 다르게 하거나 한 행을 지운다 |
| `같은 조합이 두 번 이상 적혀 있습니다: …` | 같은 옵션값 묶음이 조합 시트에 두 번 | 한 행만 남긴다 |

**참조 — 시트끼리 가리키는 키가 안 맞는다**

| 문구 | 원인 | 조치 |
|---|---|---|
| `"상품" 시트에 없는 상품키를 참조했습니다: …` | 자식 시트(옵션·조합·카테고리·구매제약)에만 남은 **고아 행** | 상품 시트에서 그 행을 지웠다면 자식 행도 같이 지운다. `read_form.py` 결과의 `고아행` 이 목록을 보여 준다 |
| `[…] 이미지 시트에 없는 이미지키를 참조했습니다: …` | 대표·부가·본문이 가리키는 키가 이미지 시트에 없다 | 이미지 시트에 그 키의 행을 더하거나, 참조를 지운다 |
| `카테고리 경로를 찾을 수 없습니다: …` | 존재하지 않는 카테고리 경로 | `read_form.py` 결과의 `카테고리참조` 목록에 있는 문자열만 쓴다 |
| `카테고리 경로가 모호합니다(같은 이름의 카테고리가 둘 이상): …` | 같은 이름의 카테고리가 여럿이라 하나로 못 정한다 | 더 깊은 경로로 적어 구별한다 |

**중복·필수**

| 문구 | 원인 | 조치 |
|---|---|---|
| `상품키가 중복되었습니다: …` | 상품 시트에 같은 상품키가 둘 | **둘 다 떨어진다.** 하나를 다른 키로 바꾼다 |
| `이미지키가 중복되었습니다: …` | 이미지 시트에 같은 이미지키가 둘 | 한 행만 남긴다 |
| `같은 카테고리가 중복 지정되었습니다: …` | 한 상품에 같은 경로가 두 번 | 한 행만 남긴다 |
| `구매제약은 상품당 한 행만 쓸 수 있습니다: …` | 구매제약 시트에 같은 상품이 두 행 | 한 행만 남긴다 |
| `대표 카테고리는 정확히 1개여야 합니다 (현재 …개).` | 대표여부 `Y` 가 0개거나 2개 이상 | 정확히 한 행만 `Y` |
| `상품키는 필수입니다.` / `이미지키는 필수입니다.` / `원본은 필수입니다: …` | 필수 칸이 비었다 | 채운다 |
| `상품명은 필수입니다.` | 신규 행에 상품명이 없다 | 채운다 (수정 행에는 걸리지 않는다) |
| `판매가는 필수입니다 (판매가 없이 게시할 수 없습니다).` | 신규 행에 판매가가 없다 | 채운다 |

| 계열 | 예 | 조치 |
|---|---|---|
| 길이 | `…은(는) …자 이하여야 합니다 (현재 …자).` | 줄인다 |
| 숫자 | `…는 0보다 큰 숫자여야 합니다: …` · `…는 정수여야 합니다 (원화는 소수 단위가 없습니다): …` · `…는 …~… 범위의 정수여야 합니다: …` | 숫자만, 정수로 |

| 문구 | 원인 | 조치 |
|---|---|---|

|---|---|---|

| 문구 | 원인 | 조치 |

### `이미지 대기` 에서 멈춤 — 가장 흔하고 가장 위험하다

**이 단계의 탈출로는 「세션 취소」뿐이다.** 「제외」는 `검토 가능` 이후에만 되므로 여기서는
쓸 수 없다. 취소하면 그 세션의 작업이 전부 날아간다. 그래서 이미지가 안 올라가는 원인을
정확히 가르는 것이 중요하다. 셋뿐이다.

**① 파일명이 다르다.** 화면의 **「올려야 하는 파일」** 목록에 있는 이름과 정확히 같은
파일이어야 한다. 비교는 **경로를 뗀 이름**으로, 대소문자와 앞뒤 공백을 무시하고 한다.
폴더 구조는 보지 않으므로 하위 폴더가 달라도 이름이 같으면 같은 파일 취급이다.
→ 목록의 이름 그대로 파일 이름을 바꾼 뒤 다시 올린다.

**② 포맷이나 용량이 안 맞는다.** 파일은 있는데 업로드가 실패한다. 자리마다 제약이 다르다:

| 쓰이는 자리 | 허용 포맷 | 최대 크기 |
|---|---|---|
| 대표이미지·부가이미지 | **jpg · png · webp 만** | **10MB** |
| 상세설명 본문 | 이미지 전부 | 20MB |

→ `.gif`·`.heic`·`.bmp` 를 대표이미지로 쓸 수 없다. jpg/png/webp 로 변환한 뒤, **파일명은
이미지 시트에 적힌 그대로 유지**해서 다시 올린다(확장자를 바꿔야 한다면 양식의 이미지
시트도 같이 고쳐 새 세션으로 올려야 한다).

**③ 요구 목록에 없는 파일만 올렸다.** 화면이 "요구 목록에 없어 건너뛴 파일 N건" 이라고
표시한다. 그 파일들은 올라가지 않는다.
→ 목록에 있는 파일을 올린다.

일부만 실패했다면 **「실패한 것만 다시 시도」** 를 먼저 눌러 본다 — 일시적 실패였다면
그것으로 끝난다.

**확보하지 못한 이미지 때문에 멈췄다면 되돌릴 방법이 없다.** 취소하고, 이미지 시트에서
그 행을 빼고 새 세션으로 올린다. 이미지는 나중에 상품 상세 화면에서 붙인다. — 애초에
`SKILL.md` 절대 규칙 8 이 이 사고를 막으려는 것이다.

### `실패` 배지

슬라이스가 **10회 연속 실패**하면 이 상태로 확정된다. **재시도·재개로 풀리지 않는다.**
화면도 "이 상태는 재시도나 재개로 풀리지 않습니다" 라고 알려 준다. 「세션 취소」만 남는다.

취소한 뒤에는 원인을 모른 채 같은 파일을 다시 올리지 않는다 — 배너에 표시된 오류 문구를
§2 에서 찾아 원인을 먼저 가른다. 문구가 §2 에 없으면 §2.3 마지막 항목대로 에스컬레이션한다.

### `검토 가능` 인데 임시 버전이 없는 행

**고장이 아니다.** 행 옆에 이런 배지가 붙는다:

- `판매정책만 적용 (새 버전 없음)` — 조합 시트의 판매정책 4칸만 바뀐 행이다. 판매정책은
  상품 버전에 담기지 않고 발행 시점에 바로 적용되므로 새 버전을 만들 이유가 없다
- `변경 없음 (새 버전 없음)` — 실제로 바뀐 값이 하나도 없는 행이다

둘 다 정상이고, 발행하면 의도한 대로 반영된다.

### `검토 가능` 에서 재시도가 남기는 부작용

「draft 실패 행 재시도」는 **신규 상품 행에서 누를 때마다 내부 등록 기록이 한 번 더
쌓인다.** 원인을 확인하기 전에 반복해서 누르지 않는다. 실패 이유를 §2 에서 먼저 가른다.

### `취소됨` 이후 정리가 안 끝난다

「임시 데이터 정리」는 **한 번에 100행씩** 처리한다. 남은 수가 0 이 될 때까지 반복해서
