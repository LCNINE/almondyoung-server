# 자료실 결제 내역 반영 안내

> 이 세션에서 테스트를 먼저 작성하고, 변경 범위에 맞춰 검증하며 구현한다.

**목표:** 이슈 #1076에서 승인한 HTML 시안을 적용한다. 결제가 완료됐지만 다운로드 권한이 아직 없는 디지털 주문을 표시하고, 실제 권한이 생길 때까지 수동으로 다시 확인할 수 있도록 한다.

**구조:** 고객의 최근 Medusa 주문을 최대 100건 조회하고, 취소·환불 상태를 제외한 결제 확정(captured) 디지털 주문을 추린다. 이후 core DB에서 해당 주문들의 활성 다운로드 권한을 일괄 확인한다. 기존 자료실의 페이지 나누기와 필터는 이 확인 작업과 독립적으로 유지한다. 자동 새로고침이나 주문 동기화 방식은 변경하지 않는다.

**사용 기술:** NestJS/Drizzle, Next.js/React/Tailwind, Jest, Vitest.

**요구사항:** `/tmp/almond-library-preview/index.html`의 승인된 시안과 이 대화를 기준으로 한다. 안내 문구는 “결제가 완료되었어요. 다운로드를 준비하고 있습니다.”로 표시한다. 정상적인 폴링 대기 시간은 최대 5분 정도로 안내하고, “다시 확인하기” 버튼을 제공한다. 시간이 지났다는 이유만으로 안내를 숨기지 않는다.

## 제약사항과 검토 항목

- 인증된 고객 본인의 Medusa 주문에 대해서만 권한 반영 상태를 반환한다. 회수된 권한은 제외한다.
- 자료실의 페이지 위치와 사용 여부 필터에 관계없이 일괄 확인한다. 기존 보유 상품 때문에 새 주문의 반영 대기 안내가 숨겨지면 안 된다.
- 무통장입금은 입금대기 표시가 남아 있어도 결제 상태가 captured이면 대상에 포함한다. 미결제·취소·환불 신청·환불 완료 주문은 제외한다.
- 연동 API 조회가 실패했을 때 반영 대기 상태라고 단정하거나 기존 보유 상품을 숨기지 않는다. 수동 재시도 방법을 제공한다.
- 추가 조회 범위는 최근 주문 최대 100건으로 제한한다. 타이머, 주문별 개별 HTTP 호출, 마이그레이션, 새 환경 변수는 추가하지 않는다.
- 화면 진입 또는 수동 재확인 시 Medusa 주문 목록 API를 1회 호출한다. 디지털 결제 주문이 있으면 core의 권한 상태 API를 추가로 1회 호출한다. 권한 상태 API 자체는 Medusa를 호출하지 않고 core DB만 조회한다.

## 작업 목록

- [x] 일괄 입력 개수 제한과 권한 조회 범위를 검증하는 core 테스트를 먼저 작성한다. 이후 `{ grantedOrderIds: string[] }`를 반환하는 `POST /library/ownerships/order-status`를 구현한다.
- [x] 결제 완료 디지털 주문 선별과 반영 대기 판정을 검증하는 스토어프런트 테스트를 먼저 작성한다. 선별 로직, 일괄 API 호출, 페이지 연결을 구현한다.
- [x] 반영 대기 안내와 상품 카드, 수동 새로고침, 확인 중·오류 피드백을 구현한다. 기존 권한 필터와 페이지 나누기를 유지하고, 대기 카드가 있으면 빈 목록 안내를 숨긴다.
- [x] 관련 core 테스트를 직렬로 실행하고, 스토어프런트 테스트·타입 검사·변경 파일 서식 검사를 수행한다. 전체 변경사항을 검토하고 실제 컴포넌트를 렌더링해 데스크톱·모바일 화면을 확인하고 캡처한다.

## 결정 사항

- 기존의 변경사항 없는 작업 디렉터리에서 시작했다. 후속 요청에 따라 커밋·푸시·운영 배포를 진행하고, 배포 확인 후 이슈 #1076을 닫는다. PR은 만들지 않으며 폴링은 변경하지 않는다.
- 반영 대기 상태는 주문 단위로 판단한다. 한 주문의 자동 권한 부여는 트랜잭션으로 처리되므로, 활성 권한이 존재하는지를 반영 완료의 기준으로 삼는다.

- core 자료실: 테스트 묶음 5개, 테스트 47개 통과. 실행 명령: `corepack yarn --ignore-engines test --runInBand --watchman=false apps/core/src/modules/library`.
- 스토어프런트 변경 기능: 파일 3개, 테스트 23개 통과. 권한 부여 도중 상태·목록 조회가 엇갈리는 문제, 제외해야 할 결제 상태, 일괄 조회 입력 제한, 빈 목록·오류 상태, 반영 대기 UI 동작을 검증했다.
- 스토어프런트 전체: 파일 85개 통과, 1개 실패. 테스트 634개 통과, 2개 실패. 변경하지 않은 `src/i18n/messages/locale-parity.test.ts`에서 en/ja의 `logoContest.detail.description` 키 누락으로 실패했다.
