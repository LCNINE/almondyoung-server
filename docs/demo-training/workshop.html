SCENARIO A · SECOND HALF

남은 6개를 받아 잔량을 0으로 만듭니다

  1. 리테일이 같은 발주 상세에서 입고 4 / 남음 6을 확인합니다.
  2. 물류가 같은 발주를 열어 입고 수량 6을 확정합니다.
  3. 6개를 DEMO-A-01-01에 적치합니다.
  4. 리테일이 전량 입고와 발주 잔량 0을 확인합니다.
  5. 물류가 입고대기 0과 입고내역 4+6을 인계합니다.

통과 기준

발주실발주 10 · 입고 10 · 남음 0
입고내역4 + 6, 두 작업 구분
적치미적치 0
재고다른 작업이 없을 때 시작 대비 +10
설명입고 확정과 적치 완료 차이를 설명
남은 수량 6을 잔량 포기로 없애면 이 실습은 실패입니다. 2차 실물 6개를 입고·적치해야 합니다.

SCENARIO C · SHORTAGE TO RECOVERY

부족 주문을 보충하고 다시 출고 준비합니다

  1. 안내자가 재고 부족 시나리오로 주문을 만듭니다.
  2. 리테일은 부족 SKU·수량과 미충족 예약을 확인합니다.
  3. 부족분을 발주하고 품목별 실행합니다.
  4. 물류는 부족분을 입고·적치합니다.
  5. 관리 담당이 출고 준비를 다시 확인합니다.
  6. 물류가 동일 주문의 송장을 스캔해 출고를 완료합니다.

SCENARIO D & E

다상품과 복구 실습은 승인된 경계 안에서만 합니다

D · 여러 상품 주문

  • 무작위 여러 상품 · 기본 주문 5건
  • 주문당 상품 종류 2 · 품목당 1–3개
  • 선택 상품이 있으면 그 범위에서만 추첨
  • 위치별 피킹·포장단위 대사
  • 같은 요청 재확인에서 상품이 바뀌지 않음

배포 화면과 5건 × 2종 acceptance를 확인했습니다. 같은 request ID 재시도에서 run·품목·주문 ID가 모두 같았습니다.

E · 예외와 복구

  • 다른 상품 오스캔 → 수량 불변
  • 부분 수령 → 잔량 유지
  • 응답 유실 fixture → 같은 작업 재확인
  • 성공 이중 반영 0
  • 다음 진행 방법을 교육생이 설명

의도적으로 네트워크를 끊거나 운영 데이터를 손상시키지 않습니다. 승인된 예외 fixture만 사용합니다.

새 다상품/보충 콘솔이 배포되기 전에는 이 페이지를 개념 교육으로만 사용합니다.
