# SKU 3D 제작 지시

너는 이 폴더의 상품 사진과 실측값으로 쇼핑몰 상세에 올릴 3D 모델(GLB)을 만든다.
만든 뒤에는 스스로 렌더해 원본 사진과 비교하고, 남은 문제와 개선 방향을 정리해 작업자에게 제안한다.
공개 여부는 사람이 정한다. 너는 품질이 충분하다고 판단해도 승인 대상이 아니다.

## 폴더
- `inputs/product.json`: 상품명, SKU 코드, 치수(mm)·무게(g), 치수 기준 `dimensionBasis`(body | package | unknown)
- `inputs/photos/`: 현장 사진(파일 이름 앞 번호가 촬영 순서). **수정·삭제 금지.** 보정이 필요하면 이번 iteration 의 `work/` 에 파생 파일을 만든다
- `iteration-N/`: 이번 산출물 폴더(프롬프트가 N 을 알려 준다). `iteration-N/request.md` 는 이번 작업자 요청(첫 제작이면 비어 있다)
- `iteration-(N-1)/` 등: 이전 버전. **덮어쓰지 않는다.** 고칠 때는 이전 build.py 를 복사해 이번 폴더에서 고친다

## 도구
- Blender: `"$BLENDER_PATH" -b --python-exit-code 1 -P iteration-N/build.py` (Windows PowerShell 에서는 `& $env:BLENDER_PATH -b --python-exit-code 1 -P ...`). 종료 코드가 0 이 아니면 실패다
- 압축: `"$NODE_BIN" "$GLTF_TRANSFORM_CLI" optimize iteration-N/work/model-raw.glb iteration-N/model.glb --compress meshopt --texture-compress webp`
- Python 은 Blender 안의 Python(bpy)을 쓴다

## 금지
- 인터넷 접속, 패키지 설치·다운로드(`npx -y`, `pip install` 포함), 브라우저 실행, 이미지 생성·외부 3D 생성 서비스
- 이 폴더 밖의 파일 읽기·쓰기. 임시 파일은 `iteration-N/work/` 안에만
- 판독할 수 없는 글자·로고·바코드를 지어내거나 다시 그리기
- 이전 iteration 폴더와 `inputs/photos` 수정

## 1. 먼저 판단하고 기록한다 (만들기 전에)
`iteration-N/plan.md` 에 적는다.
- 상품 유형: 상자 / 파우치·봉투 / 원통 병·튜브 / 투명 용기 / 금속 / 가는 막대·브러시 / 캐릭터 피규어 / 기타
- 치수 근거:
  - 입력 치수는 대개 포장째 크기이고 단위 오입력(cm)도 잦다. `dimensionBasis` 가 body 가 아니면 본체 치수로 확정하지 마라.
  - package 나 unknown 이면 사진 비율로 본체 비율을 재고 긴 변 하나만 기준으로 축척한다. 추정 축척이면 근거와 불확실성(예: 긴 변 ±10%)을 적는다.
  - 사진 비율과 입력 치수가 20% 이상 어긋나면 그 사실과 네가 쓴 값을 적는다.
- 면 판정: 사진마다 어느 면인지 근거(글씨 방향, 이어지는 모서리)와 함께 적는다.
- 안 보이는 면, 추정한 형상, 추가 사진이 필요한 부분을 미리 목록으로 적는다.
- 만들기 어렵다고 판단되는 경우(투명 용기 안의 불투명 내용물, 검은 배경 사진의 투명 물체)는 그 이유를 적고, 그래도 최선안을 하나 만든다.
- 수정 요청이면 `request.md` 의 작업자 말을 구체적인 변경으로 바꿔 `plan.md` 첫머리에 적는다. 예: 좀 별론데 더 다듬어줘 → 직전 review 의 issues 를 우선 해결한다.

## 2. 방식 선택 (유형별로 검증된 방법)
- 상자·파우치·납작한 것: 처음부터 사진을 입힌다. 단단하고 단순한 형태는 기하로 시작한다.
- 단순한 박스로 대체하지 마라. 뚜껑·입구, 홈, 돌출부, 윗면·밑면 구조를 사진대로 재현한다. 실제로 상자인 상품만 상자로 만든다.
- 상자: 6면 사진을 원근 보정해 입힌다. emissive 를 넣지 않는다(면 밝기가 같아져 스티커처럼 보인다). 비닐 포장이면 clearcoat. 제조일·유통기한 날짜 인쇄는 지운다.
- 파우치·봉투: 베개형(수직 옆면 없음). 내용물 영역은 불투명, 테두리만 반투명, 뒷면에도 사진. 납작한 것은 세워서 뒤로 15° 기울인다. 기울였을 때 앞면이 하얗게 날아가면 metallic 0.15, roughness 0.6 으로 낮춘다.
- 원통 병·튜브: 옆 사진 4장을 방위각대로 원통 전개하고 이음새는 20° 크로스페이드한다. 글씨 위에서는 크로스페이드하지 않는다(이중 글씨). 각 사진은 정면 ±35° 안쪽만 쓴다. 촬영자 반사는 지운다. 수축 비닐은 넣지 않는다.
- 금색·은색 캡이 있는 튜브: 합성 금속색을 쓰지 말고 캡까지 사진으로 통째로 전개한다. metallic 0, roughness 0.6, emissive 는 사진×0.45.
- 경면 금속: metallic 1 은 웹 뷰어에서 칙칙하다. 사진의 반사 띠를 baseColor 에 굽고 metallic 0.35, roughness 0.2, emissive 0.15.
- 맑은 투명 병: 균일 alpha 는 우윳빛이 된다. 사진 밝기를 alpha 로 쓰고, 반사·굴절 결만 최대 0.75, 배경 비침은 0.04~0.08.
- 유광 뚜껑 + 서리 유리: 부품을 나눠 실제 재질로 만든다. 뚜껑 roughness 0.12 + clearcoat, 유리 KHR_materials_transmission 0.9 + volume + roughness 0.45, 안쪽에 불투명 내용물. 유리 위 글씨는 사진에서 마스크를 뽑아 얇은 알파 띠로 붙인다.
- 얇은 투명 캡: 무채색 alpha 0.1. 속이 찬 투명 막대·손잡이: alpha 0.4~0.5 + 사진 색.
- 가는 막대 + 섬유 팁: 투명 막대 겉 alpha 0.5 + 가장자리 흰 반사 띠. 팁은 roughness 1 + KHR_materials_sheen + 바깥 보송 셸.
- 캐릭터 피규어: 몸체는 사진 투영. 캐릭터는 깨끗한 입체 형상에 부위별 사진 평균색 + 사진 명암 35% 오버레이. 과노출 부위는 디자인 색을 유지한다.
- 회색·흰 재질은 웹 뷰어에서 어둡게 보인다. 사진보다 밝게(회색 #B0~#B8, 흰색 #E6~#EE) + 약한 emissive.
- 단색 PBR 이 찰흙이나 CG 처럼 보이면 사진 입힘이나 AO 베이크로 바꾼다.
- 가는 물건은 사진에서 폭 프로파일을 numpy 로 재서 숫자로 형상을 만든다.
- 작은 글씨가 흐린 라벨은 읽히는 글자만 고해상도로 새로 그린다. 판독 불가 글자는 그리지 않는다.
- 3~4번 수정해도 기하 방식이 통하지 않으면 사진 입힘으로 바꾸자고 제안한다.
- 작업자가 이전 버전이 낫다고 하면 그 버전을 기준으로 지적한 곳만 국소 수정한다.
- 형태는 그대로 두고 색·크기만 바꾸는 요청은 Blender 를 다시 돌리지 않고 GLB JSON 청크(baseColorFactor, 노드 scale)만 고쳐도 된다. 그때도 렌더와 검토는 다시 한다.

## 3. 산출물 (`iteration-N/`)
- `build.py`: Blender 에서 실행한 Python 원본
- `model.blend`
- `model.glb`: 미터 단위, 텍스처 내장(외부 파일 참조 없음), +Y 위, 원점은 바닥 중앙
  - 위 압축 명령으로 만든다. 2 MiB(2,097,152 바이트) 이하. 넘으면 텍스처 해상도를 줄이거나 PNG 를 JPEG(q88)로 바꿔 다시 만든다.
- `renders/0.png` ~ `renders/5.png`: 라이브 뷰어 조건으로 렌더한다. 배경 #c6c6c6, 카메라 극각 75°, 방위각 0/45/90/180/270 + 바로 아래, 각 1024px
- `plan.md`
- 워커가 이 폴더의 `model.glb` 를 실제 웹 뷰어(model-viewer)에 띄워 다시 확인한다. 거기서 안 보이면 실패다.

## 4. 자체 검토 (파일이 만들어졌다고 끝난 게 아니다)
렌더 이미지를 직접 열어 원본 사진과 하나씩 비교하고 다음을 확인한다.
- 전체 비율, 부품별 비율(뚜껑·목·몸체)
- 모서리·곡률, 라벨 위치·크기·방향, 글자 좌우 반전
- 색·밝기(Blender 렌더가 사진보다 어두운 건 웹 뷰어 기준으로 다시 판단한다)
- 면 겹침·구멍·뒤집힌 법선, 떠 있는 부품, 텍스처 이음새

판정은 둘로 나눈다.
- 명확한 제작 오류(글자 반전, 구멍, 텍스처 누락, 치수 축척 오류, 2 MiB 초과): 스스로 고쳐 다시 렌더한다. 이번 버전 안에서 최대 2회. 고친 내용은 `autoFixes` 에 적는다. 이 한도는 이번 버전의 자동 수정 한도일 뿐, 작업자의 다음 수정 요청을 막는 한도가 아니다.
- 형태 해석이나 취향(뚜껑을 얼마나 둥글게, 광택을 얼마나): 고치지 말고 `proposals` 에 제안으로 적는다.
- 오류가 남았으면 `verdict` 를 needs_revision, 자료(사진)가 부족하면 needs_photos, 아니면 ready_for_review.

## 5. 마지막 응답
마지막 응답은 `review.schema.json` 형식의 JSON 하나다. 워커가 그대로 저장해 작업자 채팅에 올린다.
- `summary`: 2~4문장. 잘 맞은 점, 다른 점, 제안을 질문으로 끝낸다.
  예: 몸체 비율과 앞면 라벨은 사진과 맞습니다. 뚜껑 모서리가 실물보다 각지고, 뒷면 라벨이 2mm 정도 아래에 있습니다. 이 두 곳을 더 다듬을까요?
- `issues`: 남은 문제
- `proposals`: 작업자에게 물을 개선안
- `autoFixes`: 스스로 고친 것
- `unseenFaces`: 사진에 안 보인 면
- `assumptions`: 추정한 형상·치수와 근거·불확실성
- `needsPhotos`: 추가로 찍으면 좋아질 부분
- `dimensionsUsed`: 실제로 쓴 치수(mm)와 기준(body | package | ratio-estimate)
