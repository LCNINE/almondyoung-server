# 검색 0건 → 미취급 키워드 소싱 리포트

고객이 우리 사이트에서 검색했는데 **결과가 0건**이었고, 그 검색어로 **다른 사이트에서는
실제로 상품이 팔리고 있는** 키워드를 뽑아 엑셀로 정리한다. 소싱 후보 발굴용이다.

## 필요한 것

| 단계 | 준비물 |
|---|---|
| 1. `collect.py` | Python 3 |
| 2. `naver.js` | **ego-browser(egolite) + 네이버 로그인** — 네이버쇼핑이 로그인을 요구한다 |
| 3. `build.py` | Python 3 + `openpyxl` (`pip3 install openpyxl`) |

egolite 가 없으면 2단계만 못 돌린다. 1·3단계는 그대로 돌아가서 "우리 사이트에서
0건인 키워드"와 "노출 결함" 시트까지는 나온다 — 빠지는 건 시중 판매 확인뿐이다.

## 매일 돌리기

Claude Code 에 아래를 그대로 붙여넣으면 된다.

```
scripts/ops/search-zero-hit 로 검색 0건 미취급 키워드 리포트 만들어줘.
기간은 어제 하루. 다 돌면 소싱 후보 상위 20개랑 노출 결함 건수 알려줘.
```

기간을 바꾸려면 그 문장만 고친다 — "최근 7일", "6월 18일부터 오늘까지" 등.

## 파이프라인

세 단계다. 2단계는 브라우저를 쓰므로 사람 눈으로 진행을 볼 수 있다.

```bash
# 1) 검색 로그에서 0건 키워드 수집 → 지금도 0건인지 실측 → 상품 인덱스와 대조
python3 collect.py --since 2026-08-27 --min-count 2

# 2) 네이버쇼핑에서 시중 판매 여부 확인 (증분 저장 — 끊기면 다시 실행하면 이어서 함)
ego-browser nodejs < naver.js

# 3) 판정해서 엑셀 생성
python3 build.py --out ~/Downloads/아몬드영_검색0건_미취급_키워드.xlsx
```

2단계는 한 번에 120개씩 처리한다. 대상이 더 많으면 `done N/M` 이 M 에 닿을 때까지
같은 명령을 반복 실행한다.

## 판정이 갈리는 지점

**"검색 결과 > 0" 이 "취급 중"을 뜻하지 않는다.** 오타 교정과 fuzzy 매칭 때문에
엉뚱한 상품이 걸려 나온다. 그래서 결과 건수가 아니라 **실제 나오는 상품명**으로 가른다.

- `라몽` → 32건이 전부 `brand = 라몽 LA:MON` → 취급 중
- `롱타임래쉬` → 5건이 전부 무관한 롯드·램프 → 실질 미취급

**0건이라고 다 미취급도 아니다.** 상품이 있는데 멤버십 전용이라 비회원에게만 0건으로
보이는 경우가 있다. `퍼마색소`는 103회 검색됐지만 우리는 퍼마 색소를 53개 갖고 있다.
이런 건 `노출 결함 0건` 시트로 따로 빠진다 — 소싱이 아니라 노출 정책 문제다.

## 오탐을 고치는 법

`verdicts.json` 하나만 고친다. 코드는 건드릴 필요 없다.

```jsonc
{
  "trade": {                        // 소싱 후보로 강제
    "미쟝센": "미쟝센 퍼펙트 세럼 샴푸 / 쉽고빠른 거품 염색약 (헤어)"
  },
  "other": ["마중물", "멤버쉽"]      // 타 업종으로 강제
}
```

리포트를 볼 때마다 잘못 분류된 키워드를 여기 추가하면 다음 실행부터 정확해진다.
자동 분류가 자주 틀리는 자리는 둘이다.

- **검색어가 짧은 일반명사** — `마중물`이 작두펌프, `멤버쉽`이 차트지로 걸린다.
- **네이버가 검색을 막은 키워드** — `마취크림`, `롱타임`은 결과 자체를 안 준다.
  `시중 확인 불가` 시트에 모이니, 업계 용어로 보이면 직접 찾아 `trade` 에 넣는다.

## 알아둘 것

- 검색 로그는 **2026-04-22** 부터 있다. 그 이전은 데이터가 없다.
- 실측은 `page=2` 로 검색 API 를 부른다. `SearchService` 가 첫 페이지만 로그에
  기록하므로, 실측 자체가 0건 통계를 부풀리지 않는다. 이 규칙을 깨지 말 것.
- `--min-count 2` 가 기본이다. 1회짜리는 봇·오타 노이즈가 대부분이라 뺀다.
  기간이 하루처럼 짧으면 `--min-count 1` 로 낮춰야 건수가 잡힌다.
