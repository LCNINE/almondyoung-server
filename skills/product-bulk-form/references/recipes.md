자주 오는 세 가지 요청의 구체적 절차. 어느 것이든 시작은 `read_form.py`, 끝은
`write_form.py` 다.

## 1. 카테고리 대량 이동

"이 상품들 전부 `여성패션>니트` 로 옮겨줘" 같은 요청.

1. `python3 scripts/read_form.py <파일>` 로 읽는다
2. **대상을 상품 시트가 아니라 `카테고리` 로 고른다.** 각 상품의 `카테고리` 배열에 현재
   경로가 들어 있다. "지금 `여성패션>티셔츠` 인 것"처럼 조건이 카테고리면 그 배열로 거른다
3. 사용자에게 **대상 목록을 상품명과 함께 보여주고 확인받는다.** 카테고리는 노출 위치라
   틀리면 발행 후에나 드러난다
4. 변경 JSON 에 각 상품의 `카테고리` **행 목록만** 담는다. `필드`·`옵션`·`조합` 은 담지
   않는다

```json
{ "변경": [
    { "상품키": "P-000001",
      "카테고리": [{ "categoryPath": "여성패션>니트", "isPrimary": "Y" }] },
    { "상품키": "P-000002",
      "카테고리": [{ "categoryPath": "여성패션>니트", "isPrimary": "Y" }] }
] }
```

주의할 점:

- `카테고리` 를 주면 그 상품의 카테고리 행이 **통째로 교체된다.** "옮기기"가 아니라 "이걸로
  다시 정하기"다. 기존 카테고리를 남기려면 그 행도 같이 실어야 한다
- **`isPrimary: "Y"` 는 상품마다 정확히 1개.** 0개나 2개면 `write_form.py` 가 막는다:
  `'P-000001' 의 대표 카테고리는 정확히 1개여야 합니다 (현재 2개).`
- 경로는 `read_form.py` 결과의 `카테고리참조` 목록에 있는 문자열을 쓴다. 그 목록에 없으면
  업로드 후 `카테고리 경로를 찾을 수 없습니다` 로 그 행이 떨어진다
- **행을 지우지 않는 것이 기본이다.** 변경 JSON 에 안 담은 상품은 어차피 안 건드려지므로
  파일을 줄일 이유가 거의 없다
- 굳이 줄인다면 상품 시트에서 대상 외 행을 지우되, **그 상품의 옵션·조합·카테고리·구매제약
  행도 같이 지워야 한다.** 자식 행만 남으면 상품 시트에 없는 상품키를 가리키는 **고아 행**이
  되어 업로드 후 그 행이 오류가 된다(`"상품" 시트에 없는 상품키를 참조했습니다: P-000002`).
  `read_form.py` 는 그런 행을 최상위 `고아행` 으로 보여준다
- 반대로 **남긴 상품의 옵션·조합 행은 지우면 안 된다**(`semantics.md` §2). 지우는 방향이
  상품별로 전부 아니면 전무여야 한다는 뜻이다

## 2. 타 몰 데이터 → 신규 등록

크롤링했거나 거래처에서 받은 상품 목록을 신규 등록 양식으로 만드는 경우.

### 2.1 정리

1. 수집 데이터를 **상품 단위**로 묶는다. 옵션 행이 따로 흩어져 있으면 상품에 붙인다
2. 상품키를 발번한다 — `NEW-001`, `NEW-002` … **`P-` + 숫자 6자리는 쓰지 마라**(예약 형식)
3. 옵션이 있으면 옵션키·옵션값키를 **사람이 읽을 수 있게** 짓는다: `OPT-색상`, `OV-빨강`.
   같은 상품 안에서만 유일하면 된다
4. 조합은 옵션값키 **배열**로 준다. 문자열을 직접 잇지 않는다

```json
{ "신규": [{
    "상품키": "NEW-001",
    "필드": { "name": "베이직 니트", "basePrice": "39000", "brand": "ACME",
               "thumbnailImageKey": "IMG-N1-1", "additionalImageKeys": "IMG-N1-2|IMG-N1-3" },
    "옵션": [
      { "optionKey": "OPT-색상", "optionName": "색상", "optionValueKey": "OV-빨강", "optionValueName": "빨강" },
      { "optionKey": "OPT-색상", "optionName": "색상", "optionValueKey": "OV-파랑", "optionValueName": "파랑" },
      { "optionKey": "OPT-사이즈", "optionName": "사이즈", "optionValueKey": "OV-S", "optionValueName": "S" }
    ],
    "조합": [
      { "조합": ["OV-빨강", "OV-S"], "variantCode": "NEW-001-RED-S" },
      { "조합": ["OV-파랑", "OV-S"], "variantCode": "NEW-001-BLU-S" }
    ],
    "카테고리": [{ "categoryPath": "여성패션>니트", "isPrimary": "Y" }]
  }],
  "이미지": [
    { "imageKey": "IMG-N1-1", "sourceValue": "NEW-001-main1.jpg" },
    { "imageKey": "IMG-N1-2", "sourceValue": "NEW-001-main2.jpg" },
    { "imageKey": "IMG-N1-3", "sourceValue": "NEW-001-main3.jpg" }
  ] }
```

- 조합의 각 키는 그 상품의 **옵션 시트에 있는 옵션값키**여야 한다. 아니면
  `'NEW-001' 의 조합이 옵션 시트에 없는 옵션값키를 참조합니다: OV-검정`
- 옵션 축이 둘이면 모든 조합을 다 적을 필요는 없지만, 적은 조합만 팔린다
- 이미지키는 `이미지` 시트의 `imageKey` 와 정확히 같아야 한다. 상품 시트의
  `thumbnailImageKey`·`additionalImageKeys` 가 그 키를 가리킨다(`|` 로 나눔)

### 2.2 이미지 — AI 는 URL 을 직접 받아올 수 없다

**Claude Desktop 샌드박스의 외부 네트워크는 프록시에 막혀 있다(실측 확인).** 이미지 URL 을
받아 파일로 만드는 것은 시도해도 실패한다. 대신 **다운로드 스크립트를 만들어 사용자에게
준다.**

절차:

1. 파일명을 먼저 정한다. 규칙은 **`<상품키>-<용도><순번>.<확장자>`** — `NEW-001-main1.jpg`,
   `NEW-001-desc1.png`. 한 세션 안에서 파일명은 유일해야 한다(폴더가 달라도 이름이 같으면
   충돌한다)
2. 그 파일명을 **이미지 시트에 그대로 적는다.** 워크북은 다운로드 성공 여부와 무관하게
   완성된 상태로 나간다
3. `URL → 그 파일명` 매니페스트(CSV 나 JSON)와, 그것을 읽어 내려받는 짧은 스크립트를
   만들어 준다. 폴더 하나에 평평하게 떨어지게 한다
4. 사용자에게 안내한다: **"이 스크립트를 로컬에서 실행해 폴더를 만든 뒤, admin-web 이미지
   단계에서 그 폴더를 끌어다 놓으세요."**
5. 스크립트가 실패한 URL 을 목록으로 남기게 한다 — 그 목록이 곧 §2.3 의 누락 목록이다

매니페스트 예:

```csv
url,filename
https://example.com/a.jpg,NEW-001-main1.jpg
https://example.com/b.jpg,NEW-001-main2.jpg
```

이미 사용자 로컬 폴더에 파일이 있다면 이 단계는 통째로 건너뛴다 — 파일명만 이미지 시트에
적으면 된다.

### 2.3 확보하지 못한 이미지 (절대 규칙 8)

URL 이 없거나 다운로드가 실패한 이미지는 **이미지 시트에 적지 않는다.** 적으면 그 파일이
안 올라와 세션이 이미지 단계에서 멈추고, 취소 말고는 나갈 길이 없다.

대신 반드시 이렇게 알린다:

1. 경고한다 — "이미지 N건을 확보하지 못해 양식에서 뺐습니다"
2. **어떤 상품의 어떤 이미지가 빠졌는지 목록으로** 보여준다
3. 조치 방법을 말한다 — (a) 파일을 구해서 다시 작업하거나, (b) 이대로 등록한 뒤 상품 상세
   화면에서 이미지를 붙인다

조용히 넘어가면 사용자는 이미지가 다 들어간 줄 알고 발행한다.

## 3. MD 자체 형식 → 양식

사용자가 자기 엑셀/구글시트 표를 주면서 "이걸 양식으로 만들어줘"라고 하는 경우.

**바로 변환하지 마라. 매핑표를 먼저 만들어 확인받는다.**

1. 사용자 표의 열 이름을 전부 나열한다
2. 각각을 `columns.md` 의 내부 키에 대응시킨다. 확신이 없으면 `?` 로 둔다
3. 표로 보여주고 확인받는다

```
| 사용자 표의 열 | 양식 열 | 내부 키 | 비고 |
|---|---|---|---|
| 제품명 | 상품명 | name | |
| 정가 | 시중가 | marketPrice | |
| 판매금액 | 판매가 | basePrice | |
| 원가 | 공급가 | supplyPrice | 맞습니까? |
| 컬러 | 옵션값명 | optionValueName | 옵션 시트로 갑니다 |
| 재고 | — | — | 양식에 없습니다(재고는 별도) |
```

4. 확인받은 뒤에만 변환한다

주의할 점:

- **양식에 없는 열은 "없다"고 분명히 말한다.** 재고·매칭·채널 연동은 이 양식의 범위 밖이다
- 단위를 확인한다 — 가격이 `39,000원`·`39000`·`39.0` 중 무엇인지. 양식에는 숫자만 넣는다
- 불리언은 `Y`/`N` 대문자만이다. 사용자 표의 `O`·`예`·`TRUE` 는 변환해야 한다
- 날짜는 `YYYY-MM-DD` 로 맞춘다 (KST 로 해석된다)
- 한 상품에 옵션이 여럿이면 사용자 표는 보통 옵션마다 한 줄이다. **상품 단위로 접어서**
  상품 시트 1행 + 옵션 시트 N행으로 나눈다
