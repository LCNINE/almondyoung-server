# 양식의 의미론

이 문서는 "양식에 이렇게 적으면 시스템이 무엇으로 읽는가"만 다룬다. 열 이름과 내부 키는
`columns.md`, 화면 절차는 `workflow.md` 를 본다.

## 0. 최소 도메인

- **상품(master)** 아래에 **버전**이 여럿 있고, 그중 하나만 **판매 중(active)** 이다. 양식은
  판매 중인 버전을 프리필하고, 업로드는 **임시 버전(draft)** 을 만든다. 발행해야 판매 중인
  버전이 바뀐다 — 발행 전까지 쇼핑몰에는 아무 변화가 없다.
- **옵션 그룹 → 옵션값 → 조합**. `색상`(그룹) 밑에 `빨강`·`파랑`(값)이 있고, 값을 조합한
  것이 실제 판매 단위(품목)다. 그룹이 둘이면 조합은 `빨강+S` 처럼 값 둘을 잇는다.
- **카테고리**는 이름 경로(`여성패션>니트`)로 지정하고, 상품마다 **대표가 정확히 1개**다.
- **가격**은 상품에 `판매가`·`멤버십가` 가 있고, 조합마다 덮어쓸 수 있다. 조합 칸을 비우면
  상품 값을 상속한다.
- **이미지**는 세 자리에 쓰인다 — 대표(`대표이미지키`), 부가(`부가이미지키`), 본문
  (`상세설명` 안의 `::product-image{imageKey="…"}` 디렉티브). 앞의 둘은 같은 용도(`main`),
  본문은 별도 용도(`description`)다. 같은 파일을 대표와 본문에 쓰면 두 번 올라간다.
- 재고·상품 매칭·채널 연동·주문은 이 양식이 건드리지 않는다. 요청받으면 "양식으로는 안
  된다"고 답한다.

## 1. 빈칸의 세 가지 의미

**워크북의 셀**은 프리필 행에서 세 상태를 갖는다.

| 프리필 행의 셀 | 의미 |
|---|---|
| 원래 값이 있었는데 비웠다 | **명시적 비움** — 그 필드를 지운다 |
| 원래도 비어 있었다 | 변경 없음 |
| 값을 새로 적었다 | 그 값으로 바꾼다 |

신규 행에는 "원래"가 없으므로 빈칸은 그냥 미입력이다.

**예외 — `조합` 시트의 `선판매`·`항상판매`.** 이 두 칸은 위 표를 따르지 않는다. Y/N 두
상태뿐이라 **빈칸은 언제나 "지시 없음"**이다 — 값이 찍혀 있던 칸을 비워도 해제되지 않고
현재 값이 그대로 유지된다. 끄고 싶으면 `N` 을 **명시적으로** 적는다.

`판매상태재정의`(짝인 `출시예정일` 포함)는 표를 따른다 — 값이 있던 칸을 비우면 해제다.
다만 **신규 행에서는** 빈칸이 그냥 미입력이라 아무 정책도 걸리지 않는다.

⚠️ `조합` 시트를 변경 JSON 으로 줄 때는 그 상품의 조합 행이 **통째로 교체**되므로(§`SKILL.md`),
정책 4칸(`판매상태재정의`·`출시예정일`·`선판매`·`항상판매`)을 `read_form` 출력 그대로 되싣지
않으면 `판매상태재정의` 가 빈칸이 되어 **그 상품 전 품목의 품절·출시예정이 풀린다.** 품목코드
하나만 고치는 편집에서도 정책 칸은 반드시 함께 싣는다.

**변경 JSON** 도 같은 세 상태를 그대로 쓴다.

| 변경 JSON | 결과 |
|---|---|
| 키를 안 적음 | 셀을 건드리지 않음 = 변경 없음 |
| `"material": null` | 셀을 비움 = **명시적 비움** |
| `"material": "면 100%"` | 값을 씀 |

비우는 것은 되돌릴 수 없는 편집이다. 사용자가 "비워"라고 명시하지 않았으면 `null` 을 쓰지
않는다.

## 2. 행 삭제는 삭제가 아니다

- **상품 시트에서 프리필 행을 지우면** "이번엔 이 상품을 안 건드림"이다. 상품이 지워지지
  않는다. **임포트는 상품을 삭제하지 않는다.** 1,000행 양식에서 30건만 고칠 때 나머지 970행을
  지우는 것은 정상적인 사용법이다. 다만 지웠다면 **그 상품의 옵션·조합·카테고리·구매제약
  행도 같이 지운다.** 자식 행만 남으면 상품 시트에 없는 상품키를 가리키는 **고아 행**이 되어
  업로드 후 그 행이 오류가 된다:
  `"상품" 시트에 없는 상품키를 참조했습니다: P-000002`

  `read_form.py` 는 그런 행을 최상위 `고아행` 으로 드러낸다(어느 시트·어느 상품키인지 함께).
  `write_form.py` 는 **이번에 손댄 상품의 문제면 막고, 그 밖의 행이면 경고만 하고 파일은
  만든다** — 서버도 그런 행만 오류로 떨구고 세션은 진행시키기 때문이다. 경고는 삼키지 말고
  사용자에게 그대로 전한다.
- **카테고리 시트에 그 상품의 행이 하나도 없으면** 카테고리 변경 없음이다. 카테고리를 전부
  떼는 방법은 양식에 없다.
- **구매제약 시트도 같다** — 행이 없으면 변경 없음이고, 해제는 값 칸을 비운 **행**으로
  표현한다.

**예외: 옵션·조합 시트는 다르다.** 프리필 행의 옵션·조합 행을 지우면 "변경 없음"이 아니라
**구조 변경**으로 읽혀 그 행이 오류가 된다:

```
옵션값을 삭제할 수 없습니다: V2
조합 행을 지울 수 없습니다: V1+V2
```

즉 상품 시트에서 어떤 상품 행을 남겼다면 그 상품의 옵션·조합 행도 전부 남겨야 한다. 하위
시트를 상품 시트에 맞춰 필터할 때 이 비대칭을 반드시 지킨다.

## 3. 열 삭제가 셀 비우기보다 안전하다

직관과 반대다. 열이 **통째로 없으면** 시스템은 "이 필드는 이번에 안 건드림"으로 읽는다.
셀만 비우면 "비워라"가 된다. 그래서 "이 필드는 손대고 싶지 않다"는 요구의 답은 **셀 비우기가
아니라 열 삭제**이고, 이 스킬에서는 더 간단하게 **변경 JSON 에 그 키를 안 적는 것**이다.

`write_form.py` 는 열을 지우지 않는다. 없는 열에 값을 쓰려 하면 그 자리에서 막는다:

```
'상품' 시트에 'brand' 에 해당하는 열이 없습니다.
```

사용자가 열을 직접 지운 워크북을 줬다면 그 필드는 이번 작업 대상이 아니라는 뜻이다.

## 4. 상품키

- **`P-` + 숫자 6자리는 시스템 예약 형식**이다. 양식 다운로드가 프리필 행에 발급한다.
- 신규 상품에 이 형식을 쓰면 거부된다. `write_form.py` 가 저장 전에 잡는다:
  `'P-000123' 는 시스템 예약 상품키 형식입니다. 다른 상품키를 지어 주세요.`
- 신규 상품키는 사람이 읽을 수 있게 짓는다 — `NEW-001`, `24FW-니트-01` 처럼. 100자까지.
- **`read_form.py` 의 `출처` 필드를 믿지 마라.** `exportId` 유무로만 갈리는 워크북 단위
  근사라, 프리필 양식에 손으로 더한 신규 행도 `"프리필"` 로 나온다. 정확한 신호는 상품키
  형식이다 — `P-` + 숫자 6자리면 수정 대상, 아니면 신규.

### 양식 정보를 잃은 워크북

숨은 `_양식정보` 시트가 사라진 수정용 양식은 **다시 받아야 한다.** 시트를 복사하거나 다른
프로그램으로 저장하면 사라진다. `write_form.py` 가 이 경우를 구분해 안내한다:

```
'P-000001' 는 시스템이 발급한 상품키인데 이 파일에는 양식 정보(_양식정보)가 없습니다.
상품키를 바꾸지 말고, 상품 목록에서 양식을 다시 받아 작성해 주세요.
```

**상품키를 다른 값으로 바꿔 우회하지 마라.** 바꾸면 예약 형식이 아니게 되어 서버 가드를
비껴가고, 워크북이 "신규 전용"으로 읽혀 프리필 행 전량이 **새 상품으로 중복 생성된다.**
서버도 같은 파일을 400 으로 거부한다.

두 문구는 **그 상품키가 원본 워크북에 있었는가**로 갈린다 — `_양식정보` 시트 유무가 아니다.
원본에 있던 예약 키면 양식 정보를 잃은 프리필이므로 "양식을 다시 받아라"이고, 원본에 없던
키를 새로 지은 것이면 "다른 상품키를 지어라"다. **빈 양식(`빈 양식 다운로드`)은 정상적으로
`_양식정보` 시트가 없으므로** 거기서 지은 예약 형식 키는 후자다 — 다시 받을 프리필이 없다.

## 5. 양식으로 바꿀 수 있는 것과 없는 것

| 대상 | 신규 행 | 프리필(수정) 행 |
|---|---|---|
| 상품 스칼라 필드(이름·브랜드·소재·SEO·판매기간 등) | O | O |
| 카테고리 배정·대표 | O | O |
| 구매제약(멤버십필요·평생구매한도) | O | O |
| 이미지 참조(대표·부가·본문) | O | O |
| 옵션·옵션값의 **표시명·색상코드·정렬** | O | O |
| 조합별 판매가·멤버십가·품목코드 | O | O |
| 옵션값 **추가·삭제**, 옵션 축 변경 | O | **X** |
| 조합 **추가·삭제** | O | **X** |
| 상품 삭제 | — | **X** |

프리필 행에서 옵션값·조합을 못 바꾸는 이유는 조합의 정체성이 바뀌면 재고 매칭이 끊겨 그
품목이 재고 검사 없이 무한 판매되기 때문이다. 요청받으면 **상품 상세 화면에서 하라**고
답한다.

`write_form.py` 에서 `옵션`·`조합`·`카테고리` 를 주면 그 상품의 해당 시트 행이 **통째로
교체**된다. 그래서 프리필 행에는 `옵션`·`조합` 을 주지 않는 것이 기본이고, 표시명만 고칠
때도 **원래 행 전부**를 그대로 실은 뒤 표시명 칸만 바꿔야 한다. 일부만 주면 나머지가
사라지고 위의 "삭제할 수 없습니다" 오류가 난다.

**구매제약 시트는 `write_form.py` 로 편집할 수 없다.** 다루려면 사용자가 엑셀에서 직접
적어야 한다. 읽기는 `read_form.py` 로 된다.

## 6. 판매정책은 상품 버전에 담기지 않는다

`조합` 시트의 정책 4칸(`판매상태재정의`·`출시예정일`·`선판매`·`항상판매`)은 다른 칸과
성질이 다르다. 나머지 칸은 임시 버전에 담겼다가 발행할 때 반영되지만, **정책 4칸은 버전에
담기지 않고 발행하는 순간 바로 적용된다.**

여기서 두 가지가 따라 나온다.

- **정책 칸만 바꾼 행은 임시 버전이 아예 만들어지지 않는다.** 화면에 `판매정책만 적용
  (새 버전 없음)` 배지가 붙는다. 고장이 아니다 — 바꿀 버전 내용이 없으니 만들지 않는
  것이다. 발행하면 정책은 정상적으로 적용된다
- **버전을 되돌려도 정책은 안 돌아온다.** 상품 상세 화면에서 옛 버전으로 롤백해도 품절·
  출시예정·선판매 설정은 마지막으로 적용된 값 그대로다. 정책을 되돌리려면 정책을 다시
  지정해야 한다

빈칸의 의미가 이 4칸에서 갈리는 것(§1 의 예외)도 같은 이유다.

## 7. 가격 센티넬 `[복합 가격규칙]`

계단식·기간별 같은 복합 가격규칙이 걸린 상품은 프리필의 가격 칸에 값 대신
`[복합 가격규칙]` 이 들어 있다. **그 칸은 그대로 둔다.** 고치면 그 행이 오류가 된다:

```
복합 가격규칙 상품의 판매가은(는) 임포트로 수정할 수 없습니다: 19000
```

사용자가 그 상품의 가격을 바꿔 달라고 하면 "이 상품은 가격 규칙이 걸려 있어 양식으로는 못
바꾼다"고 답한다. 다른 필드는 평소대로 고칠 수 있다.

## 8. 이미지

### 전량 게이트 — 적은 것은 반드시 올라와야 한다

이미지 시트에 적힌 파일명은 업로드 후 3단계에서 **하나도 빠짐없이** 올라와야 세션이
전진한다. 하나가 없으면 세션이 그 자리에서 멈추고, **취소 말고는 나갈 길이 없다** — 취소하면
그 세션의 작업이 전부 날아간다.

그래서 **확보하지 못한 이미지는 시트에 적지 않는다.** 빈칸으로 두고 나중에 상품 상세
화면에서 붙이는 편이 언제나 낫다. 다만 절대 규칙 8 대로, 조용히 넘기지 말고 어떤 상품의 어떤
이미지가 빠졌는지 목록으로 보여주고 조치 방법을 말한다.

### 포맷과 용량 — 여기서도 세션이 멈춘다

파일을 확보했더라도 **포맷이나 용량이 안 맞으면 업로드가 거부되고 세션은 이미지 단계에서
그대로 멈춘다.** 앞 절의 "전량 게이트"와 같은 결과다.

| 쓰이는 자리 | 허용 포맷 | 최대 크기 |
|---|---|---|
| 대표이미지키 · 부가이미지키 | **jpg · png · webp 만** | **10MB** |
| 상세설명 본문(`::product-image{…}`) | 이미지 전부 | 20MB |

대표·부가에 `.gif`·`.heic`·`.bmp` 를 쓸 수 없다. 타 몰에서 모은 이미지가 webp 가 아닌
다른 포맷이면 **파일명을 정하기 전에** 변환 여부를 사용자에게 확인한다 — 이미지 시트에
적은 파일명과 실제 파일명이 어긋나면 그것도 같은 교착을 만든다.

### `원본` 칸에 적는 것

- **로컬 파일명** — `NEW-001-main1.jpg`. 사용자가 그 파일을 폴더째 끌어다 놓는다
- **파일 ID(UUID)** — 프리필에 이미 들어 있는 값. 건드리지 않으면 그대로 유지된다
- **URL 은 금지다.** `write_form.py` 가 막고(`이미지 원본에 URL 은 쓸 수 없습니다: …`),
  서버도 거부한다(`URL 은 지원하지 않습니다. 파일을 직접 올리거나 파일명을 적어주세요.`)

파일명 매칭은 **경로를 뗀 파일명**을 앞뒤 공백 제거 + 소문자로 비교한다. 폴더 구조는 무시
되므로 하위 폴더가 달라도 **파일명이 같으면 충돌**한다 — 한 세션 안에서 파일명은 유일해야
한다.

### 프리필 이미지는 그대로 둔다

수정 행에서 대표·부가·본문 칸을 건드리지 않으면 기존 이미지가 유지된다. 이미지 시트가 통째로
없어도 된다. 반대로 **칸을 고쳤다면** 그 키의 원본이 이미지 시트에 있어야 한다:

```
[P-000001] 이미지 시트에 없는 이미지키를 참조했습니다: IMG-9
```

### 이미지 행은 덧붙는다

`write_form.py` 의 `이미지` 목록은 시트 끝에 **추가**된다(교체가 아니다). 같은 이미지키를 두
번 적지 않는다.

## 9. 값 형식과 상한

- **다중값은 `|` 로 나눈다** — `부가이미지키`, `SEO키워드`. 예: `IMG-2|IMG-3`
- **불리언은 대문자 `Y`/`N`** — `해외직구`, `멤버십회원전용노출`, `비회원에게멤버십가숨김`,
  `도매전용`, `대표여부`, `멤버십필요`. `y`·`예`·`TRUE` 는 오류다
- **날짜는 `YYYY-MM-DD` 또는 `YYYY-MM-DD HH:mm`**, KST 로 해석된다. 날짜만 적으면
  `판매시작` 은 그날 00:00, `판매종료` 는 그날 23:59:59 다
- **`상품유형`** 은 `regular_sale` / `limited_edition`, **`배송유형`** 은 `physical` /
  `digital` 만 허용된다
- **가격은 숫자 문자열**이다. `판매가` 는 0보다 커야 하고, `멤버십가` 는 `판매가` 이하여야
  한다. 조합 칸을 비우면 상품 값을 상속하므로 상속된 값끼리도 이 규칙을 만족해야 한다
- **길이 상한**: `상품명`·`별칭`·`SEO제목` 255자, `브랜드`·`상품코드`·`판매처`·`판매분류`·
  `구매분류`·`상품키` 100자, `옵션명`·`옵션값명`·`품목코드` 100자, `색상코드` 7자
  (`#RRGGBB`)
- **개수 상한**: `부가이미지키` 5개. `최소구매수량` ≥ 1, `최대구매수량` ≥ `최소구매수량`,
  `연령제한` 0~100
- **카테고리 경로**는 `read_form.py` 가 돌려주는 `카테고리참조` 목록에 있는 문자열이어야
  한다. 없으면 `카테고리 경로를 찾을 수 없습니다: …`, 같은 이름이 둘이면
  `카테고리 경로가 모호합니다…` 로 그 행이 떨어진다

## 10. 파일 상한

한 워크북에 상품 1,000행, 파일 크기 10MB 까지다. 넘으면 업로드가 거부된다. 더 크면 나눠서
여러 번 올린다.
