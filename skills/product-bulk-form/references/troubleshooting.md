# 막혔을 때

이 문서는 **작업이 안 넘어갈 때** 연다. 양식을 만드는 중이면 `semantics.md`·`columns.md`
가 맞다. 사용자가 오류·멈춤·이상을 신고하면 다른 문서보다 여기를 먼저 본다.

## 1. 먼저 좌표를 잡는다

AI 는 사용자의 화면을 볼 수 없다. 추측으로 답하지 말고 **두 가지만 묻는다.**

1. **「엑셀 일괄 등록/수정」 화면 위쪽의 상태 배지가 무엇입니까?**
2. **화면에 뜬 문구를 그대로 붙여넣어 주세요.**

배지는 열 가지뿐이고 각각이 그 단계에서 가능한 고장을 닫아 준다:

| 배지 | 지금 무슨 일이 벌어지는가 | 사람이 할 일 |
|---|---|---|
| `접수됨` | 파일을 받아 읽기 시작함 | 기다린다 |
| `검증 중` | 행을 검사하는 중 | 기다린다 |
| `검토 대기` | 검사가 끝났다 | **검토하고 승인** |
| `이미지 대기` | 이미지 파일을 기다린다 | **파일을 올린다** |
| `임시 버전 생성 중` | 임시 버전을 만드는 중 | 기다린다 |
| `검토 가능` | 임시 버전이 만들어졌다 | **확인하고 일괄 발행** |
| `발행 중` | 발행하는 중 | 기다린다 |
| `발행 완료` | 끝났다. 쇼핑몰에 반영됐다 | — |
| `취소됨` | 취소된 세션 | 임시 데이터 정리 |
| `실패` | 되살릴 수 없는 상태 | 취소만 가능 (§3) |

**배지가 없다면** 세션이 아직 없다는 뜻이다. 세 경우다:

- 화면 자체가 안 열리거나 목록이 "이 기능은 admin·master 권한이 필요합니다." 로 뜬다 →
  권한 문제다. 양식이나 파일 문제가 아니다. 계정에 `admin` 또는 `master` 롤을 받아야 한다
- 「양식 업로드」가 거부됐다 → §2.2 (파일 오류)
- 양식을 못 받았다 → `workflow.md` §1 을 따라 다시 시도한다
- 받은 양식의 상품 수가 고른 개수보다 적다 → 고장이 아니다. **판매 중인 버전이 없는 상품은
  조용히 빠진다**(`workflow.md` §1). 목록의 「상품 수」 열은 `실제로 들어간 개수 / 요청한
  개수`로 나온다 — 두 수가 다르면 그것이다. 빠진 상품을 **신규 행으로 다시 적지 않는다** —
  그러면 중복 상품이 생긴다

**"기다린다" 단계에서 오래 머문다면** 새로고침을 한 번 해 본다. 그래도 몇 분째 같은
배지라면 §3 을 본다.

## 2. 오류 문구로 찾기

붙여넣은 문구를 아래에서 찾는다. **조치가 근본적으로 다른 네 부류**이므로 어느 부류인지
부터 가른다. 표에 없는 문구라면 §2.4 마지막 항목(에스컬레이션)을 본다.

### 2.1 행 오류 — 그 행만 떨어진다

검토 화면의 **「오류」 탭**에 뜬다. 헤더의 **「오류 목록 복사」** 버튼으로 전문을 받아
붙여넣게 하면 한 번에 여러 건을 다룰 수 있다.

**이 행들은 승인해도 진행되지 않는다** — 승인 창이 "오류 N건은 제외하고 M건을 진행합니다"
라고 알려 준다. 살리려면 **양식을 고쳐 새 세션으로 다시 올려야** 한다. 옛 세션은 「세션
취소」로 정리한다.

**구조 — 프리필(수정) 행은 옵션·조합을 못 바꾼다**

| 문구 | 원인 | 조치 |
|---|---|---|
| `옵션값을 추가할 수 없습니다: …` | 프리필 행의 옵션 시트에 없던 옵션값키를 새로 적었다 | 그 행을 원래대로 되돌린다. 옵션값 추가는 **상품 상세 화면**에서만 된다 |
| `옵션값을 삭제할 수 없습니다: …` | 프리필 행의 옵션 시트 행을 지웠다 | 지운 행을 되살린다. 상품 시트에 남긴 상품은 옵션·조합 행도 전부 남겨야 한다 |
| `조합 행을 지울 수 없습니다: …` | 프리필 행의 조합 시트 행을 지웠다 | 같음 |
| `없던 조합을 만들 수 없습니다: …` | 프리필 행에 새 조합을 더했다 | 같음 |
| `같은 옵션키에 서로 다른 옵션명이 적혀 있습니다: …` | 한 옵션키의 옵션명 칸이 행마다 다르다 | 같은 옵션키의 옵션명을 한 값으로 통일한다 |
| `옵션값키가 여러 옵션 그룹에 걸쳐 있습니다: …` | 신규 행에서 한 옵션값키를 두 옵션 그룹에 썼다 | 옵션값키는 그룹마다 다르게 짓는다 |
| `한 옵션 그룹 안에서 옵션값 표시명이 중복되었습니다: …` | 신규 행의 한 그룹에 같은 이름의 옵션값이 둘 | 이름을 다르게 하거나 한 행을 지운다 |
| `같은 조합이 두 번 이상 적혀 있습니다: …` | 신규 행에서 같은 옵션값 묶음이 조합 시트에 두 번 | 한 행만 남긴다 |

**참조 — 시트끼리 가리키는 키가 안 맞는다**

| 문구 | 원인 | 조치 |
|---|---|---|
| `"상품" 시트에 없는 상품키를 참조했습니다: …` | 자식 시트(옵션·조합·카테고리·구매제약)에만 남은 **고아 행** | 상품 시트에서 그 행을 지웠다면 자식 행도 같이 지운다. `read_form.py` 결과의 `고아행` 이 목록을 보여 준다 |
| `[…] 이미지 시트에 없는 이미지키를 참조했습니다: …` | 대표·부가·본문이 가리키는 키가 이미지 시트에 없다 | 이미지 시트에 그 키의 행을 더하거나, 참조를 지운다 |
| `카테고리 경로를 찾을 수 없습니다: …` | 존재하지 않는 카테고리 경로 | `read_form.py` 결과의 `카테고리참조` 목록에 있는 문자열만 쓴다 |
| `카테고리 경로가 모호합니다(같은 이름의 카테고리가 둘 이상): …` | 같은 이름의 카테고리가 여럿이라 하나로 못 정한다 | 더 깊은 경로로 적어 구별한다 |

**중복·필수**

| 문구 | 원인 | 조치 |
|---|---|---|
| `상품키가 중복되었습니다: …` | 상품 시트에 같은 상품키가 둘 | **둘 다 떨어진다.** 하나를 다른 키로 바꾼다 |
| `이미지키가 중복되었습니다: …` | 이미지 시트에 같은 이미지키가 둘 | 한 행만 남긴다 |
| `같은 카테고리가 중복 지정되었습니다: …` | 한 상품에 같은 경로가 두 번 | 한 행만 남긴다 |
| `구매제약은 상품당 한 행만 쓸 수 있습니다: …` | 구매제약 시트에 같은 상품이 두 행 | 한 행만 남긴다 |
| `대표 카테고리는 정확히 1개여야 합니다 (현재 …개).` | 대표여부 `Y` 가 0개거나 2개 이상 | 정확히 한 행만 `Y` |
| `상품키는 필수입니다.` / `이미지키는 필수입니다.` / `원본은 필수입니다: …` | 필수 칸이 비었다 | 채운다 |
| `상품명은 필수입니다.` | 신규 행에 상품명이 없다 | 채운다. **수정 행에는 이 검사가 안 걸리지만**, 수정 행에서 상품명을 명시적으로 비우면 여기가 아니라 §2.4(생성 실패)의 `상품명은 비울 수 없습니다.`에서 걸린다 |
| `판매가는 필수입니다 (판매가 없이 게시할 수 없습니다).` | 신규 행에 판매가가 없다 | 채운다. **수정 행에는 이 검사가 안 걸리지만**, 수정 행에서 판매가를 명시적으로 비우면 §2.4 의 `상품 판매가가 없어 가격 규칙을 만들 수 없습니다.`에서 걸린다 |

**값 형식** — 문구가 열 이름으로 시작하고 `…여야 합니다` 로 끝나면 전부 이 부류다.
`semantics.md` §9 이 규칙 전문을 갖고 있으므로 거기로 보낸다.

| 계열 | 예 | 조치 |
|---|---|---|
| 길이 | `…은(는) …자 이하여야 합니다 (현재 …자).` | 줄인다 |
| 숫자 | `…는 0보다 큰 숫자여야 합니다: …` · `…는 0보다 큰 숫자여야 합니다 (판매가 없이 게시할 수 없습니다): …` · `…는 0 이상의 숫자여야 합니다: …`(시중가 등) · `…는 정수여야 합니다 (원화는 소수 단위가 없습니다): …` · `…는 …~… 범위의 정수여야 합니다: …` | 숫자만, 정수로. 0 이하가 안 되는 칸과 0 이상이면 되는 칸이 다르니 문구를 그대로 따른다 |
| 대소 관계 | `멤버십가는 판매가 이하여야 합니다: …` · `최대구매수량는 최소구매수량 이상이어야 합니다: …` · `판매종료는 판매시작보다 뒤여야 합니다.` | 값을 맞바꾼다 |
| 열거 | `…은(는) […] 중 하나여야 합니다: …` | 허용값만 (`columns.md`) |
| Y/N | `…는 Y 또는 N 이어야 합니다: …` | **대문자** `Y`/`N` 만. `y`·`예`·`TRUE` 는 오류 |
| 날짜 | `…은(는) 'YYYY-MM-DD' 또는 'YYYY-MM-DD HH:mm' 형식이어야 합니다: …` · `…은(는) 'YYYY-MM-DD' 형식이어야 합니다: …`(출시예정일처럼 날짜만 받는 칸) · `…은(는) 존재하지 않는 날짜입니다: …` | 형식을 맞춘다 |
| 개수 | `부가이미지키는 5개까지 등록할 수 있습니다 (현재 …개).` | 5개로 줄인다 |
| 판매정책 | `판매상태재정의는 '품절' 또는 '출시예정'이어야 합니다: …` · `출시예정일은(는) 판매상태재정의가 '출시예정'일 때만 쓸 수 있습니다.` | 두 칸을 짝으로 맞춘다 |

**가격 규칙**

| 문구 | 원인 | 조치 |
|---|---|---|
| `복합 가격규칙 상품의 …은(는) 임포트로 수정할 수 없습니다: …` | `[복합 가격규칙]` 센티넬이 든 칸을 고쳤다 | **그 칸을 센티넬 그대로 되돌린다.** 이 상품의 가격은 양식으로 못 바꾼다 — 다른 필드는 평소대로 고칠 수 있다 |

**품목코드 중복** — 파일 안 중복과 다른 상품과의 중복을 가른다.

| 문구 | 원인 | 조치 |
|---|---|---|
| `[조합] 품목코드가 파일 안에서 중복됩니다: … (…)` | 같은 워크북 안에서 품목코드가 겹친다 | 괄호 안 행 번호를 보고 한쪽을 바꾼다 |
| `[조합] 품목코드를 이미 사용 중인 상품이 있습니다: …` | 이미 등록된 다른 상품이 그 코드를 쓴다 | 다른 코드를 짓는다 |

**기준(프리필) 문제** — 양식을 다시 받아야 하는 부류다.

| 문구 | 원인 | 조치 |
|---|---|---|
| `기준이 변경되었습니다. 이 상품은 양식을 다시 받아 작업해 주세요.` | 양식을 받은 뒤 그 상품이 새로 발행돼 기준이 달라졌다 | 그 상품만 양식을 다시 받아 따로 작업한다 |
| `기준 상품의 판매 중인 버전을 찾을 수 없습니다.` | 그 상품의 판매 중인 버전이 사라졌다 | 상품 상세 화면에서 상태를 확인한다. 양식으로 풀 수 없다 |
| `기준 스냅샷이 없어 수정 행을 검증할 수 없습니다. 양식을 다시 받아 주세요.` | 양식 정보가 손상됐다 | 양식을 다시 받는다 |
| `행 데이터 형식이 달라 처리할 수 없습니다. 파일을 다시 올려주세요.` | 세션 데이터가 예상 형태가 아니다 | 새 세션으로 다시 올린다 |

### 2.2 파일 오류 — 파일 전체가 거부된다

세션이 아예 안 만들어진다. 배지도 없다.

| 문구 | 원인 | 조치 |
|---|---|---|
| `필수 시트 "…" 가 없습니다.` | 시트를 지웠거나 이름을 바꿨다 | 원본 양식으로 다시 작업한다. **시트 이름을 바꾸지 않는다** |
| `"상품" 시트 필수 열 누락: …` | 필수 열을 지웠다 | 그 열을 되살린다 (`columns.md` 의 볼드가 필수 열) |
| `"…" 시트에 "…" 열이 중복되었습니다. 한 열만 남겨주세요.` | 같은 헤더가 두 열 | 한 열을 지운다 |
| `"…" 시트 행이 상한(…)을 초과했습니다. 파일을 나눠 올려주세요.` | 상품 1,000행 등 상한 초과 | 파일을 나눠 여러 번 올린다 |
| `유효한 엑셀(.xlsx) 파일이 아닙니다.` | `.xls`·CSV·손상된 파일 | `.xlsx` 로 저장해 다시 올린다 |
| `파일이 너무 큽니다. 10MB 이하만 올릴 수 있습니다.` | 10MB 초과 | 나눠 올린다 |
| `양식이 만료되었습니다. 상품 목록에서 양식을 다시 받아 작성해 주세요.` | 그 양식(exportId)을 더 못 쓴다 — 30일 만료가 가장 흔하지만, 잡 상태가 완료가 아니거나 내부 스냅샷이 손상된 경우도 같은 문구로 뜬다 | 양식을 다시 받는다. **같은 파일을 다시 올려도 안 된다** |
| `수정용 양식인데 양식 정보가 사라졌습니다. …`(전문은 `semantics.md` §4) | 워크북에 있던 시스템 예약 상품키(`P-000000` 형식)의 숨은 `_양식정보` 시트가 사라졌다(시트 복사·다른 형식 저장·다른 프로그램에서 재저장) | **상품키를 다른 값으로 바꿔 우회하지 않는다** — 바꾸면 프리필 행 전량이 신규 상품으로 중복 생성된다(아래 우회 경고 참조). 상품 목록에서 양식을 다시 받는다 |
| `이 기능은 admin·master 권한이 필요합니다.` | 계정 권한 | 롤을 받아야 한다. 양식 문제가 아니다 |

**여기서 절대 하면 안 되는 우회:** 만료·양식정보 손상 오류를 피하려고 **상품키를 바꾸지
않는다.** 바꾸면 예약 형식(`P-` + 숫자 6자리)이 아니게 되어 서버 가드를 비껴가고, 워크북이
"신규 전용"으로 읽혀 **프리필 행 전량이 새 상품으로 중복 생성된다**(`semantics.md` §4).

### 2.3 이미지 업로드 실패 — 「이미지 대기」 화면에서 뜬다

파일을 올렸는데 그 파일 옆에 실패 사유가 붙는 경우다. 문구 없이 그냥 안 넘어가는 경우는
§3 의 「이미지 대기」 절로 간다 — 여기는 **문구가 있는** 경우만 다룬다.

| 문구 | 원인 | 조치 |
|---|---|---|
| `파일 업로드에 실패했습니다. (status: 400)` | 포맷·용량이 안 맞는 파일이다 | §3 의 「이미지 대기」 ② 표에서 허용 포맷·용량을 확인하고 변환해 다시 올린다 |
| `파일 업로드에 실패했습니다. (status: 404)` | 업로드 대상 컨텍스트가 서버에 없다 | 양식·파일 문제가 아니다. **개발팀에 알린다**(file-service 쪽 설정 문제) |
| `양식에 파일ID로 적힌 이미지는 업로드로 바꿀 수 없습니다.` | 그 이미지 행은 이미 파일ID(UUID)를 갖고 있어 업로드가 필요 없는데 새 파일을 올렸다 | 그 행은 손대지 않는다. 새 파일로 바꾸려면 이미지 시트의 원본 칸을 새 파일명으로 고쳐 새 세션으로 올린다 |
| `이 세션에 없는 이미지 참조입니다. 양식의 이미지키와 용도를 확인해 주세요.` | 올린 파일이 이 세션의 이미지 시트에 없는 이미지키·용도 조합을 가리킨다 | 이미지 시트의 이미지키와 용도(대표·부가는 `main`, 본문은 `description`)를 다시 확인한다 |
| `업로드된 파일을 찾을 수 없습니다. 다시 올려주세요.` | 파일은 받아졌는데 그 사이 사라졌다(드문 경우) | 같은 파일을 다시 올린다 |
| `파일 확인에 실패했습니다. 잠시 후 다시 시도해 주세요.` | 일시적 오류다 | 잠시 후 **「실패한 것만 다시 시도」** |
| `대표·부가 이미지 용도로 올린 파일이 아닙니다 (기대 컨텍스트 …, 실제 …).` / `본문 이미지 용도로 올린 파일이 아닙니다 (기대 컨텍스트 …, 실제 …).` | 대표·부가 자리에 본문용 파일을, 또는 그 반대로 올렸다 | 올바른 자리에 맞는 파일을 다시 올린다 |
| `이미 삭제된 파일입니다.` | 참조한 파일이 file-service 에서 이미 삭제됐다 | 그 이미지를 새로 올린다 |

### 2.4 생성·발행 실패 — 양식 문제가 아닐 수 있다

`검토 가능` 화면의 **「실패」 탭**(임시 버전 생성 실패)과 `발행 완료` 화면의 **발행 실패**
블록, 둘 다 여기서 찾는다. 여기가 **스킬이 답할 수 있는 범위의 경계**다.

| 문구 | 양식으로 고칠 수 있나 | 조치 |
|---|---|---|
| `품목코드가 다른 상품과 중복됩니다: …` | **예** | 그 품목코드를 바꿔 새 세션으로 올린다 |
| `상품코드를 이미 사용 중인 다른 상품이 있습니다: …` | **예** | 상품코드를 바꾼다 |
| `입력한 값이 저장할 수 있는 길이(…자)를 넘었습니다.` | **예** | 그 값을 줄인다. 어느 칸인지 안 나오므로 긴 값부터 의심한다 |
| `계산된 판매가가 올바르지 않습니다. 가격 설정을 확인해 주세요.` | 아니오 | 그 상품의 가격 규칙 문제다. 상품 상세 화면에서 확인한다 |
| **`…에 실패했습니다. (원인: …)`** | **아니오** | **에스컬레이션.** 아래 참조 |

**임시 버전 생성 실패 — 검증은 통과했는데 여기서 처음 걸릴 수 있다.** `검토 가능` 화면의
「실패」 탭에만 뜬다. §2.1 의 상품명·판매가 필수 검사는 **신규 행에만** 걸리므로,
**프리필(수정) 행에서 상품명·판매가 칸을 명시적으로 비우면 검증은 「정상」으로 통과하고
이 단계에서 처음 죽는다.** `semantics.md` §1 의 "명시적 비움"을 그대로 실행하면 실제로
밟는 경로다.

| 문구 | 원인 | 조치 |
|---|---|---|
| `상품명은 비울 수 없습니다.` | 수정 행에서 상품명 칸을 명시적으로 비웠다 | 상품명을 다시 채워 새 세션으로 올린다 |
| `상품 판매가가 없어 가격 규칙을 만들 수 없습니다.` | 수정 행에서 판매가 칸을 명시적으로 비웠다 | 판매가를 다시 채운다 |
| `옵션 그룹 표시명은 비울 수 없습니다.` | 수정 행의 옵션 그룹 옵션명 칸을 비웠다 | 표시명을 채운다 |
| `옵션값 표시명은 비울 수 없습니다.` | 수정 행의 옵션값 옵션값명 칸을 비웠다 | 표시명을 채운다 |
| `대표이미지키를 해석할 수 없습니다: …` / `부가이미지키를 해석할 수 없습니다: …` / `상세설명의 이미지키를 해석할 수 없습니다: …` | 이미지 참조가 업로드 단계를 지나고도 파일로 안 풀렸다 | 새 세션으로 다시 올린다. 반복되면 개발팀에 알린다 |
| `조합이 옵션 시트에 없는 옵션값키를 참조합니다: … (조합: …)` | 조합 시트가 옵션 시트에 없는 옵션값키를 가리킨다 | 옵션 시트에 그 값을 추가하거나 조합에서 뺀다 |
| `기준 상품 정보가 없어 수정할 수 없습니다. 양식을 다시 받아 주세요.` | 기준 스냅샷이 없다 | 양식을 다시 받는다 |

**`(원인: …)` 이 붙은 문구는 시스템이 분류하지 못한 오류다.** `생성에 실패했습니다.
(원인: …)`(임시 버전 생성 단계) · `발행에 실패했습니다. (원인: …)`(발행 단계) 둘 다
같다. 양식을 고쳐 다시 올려도 같은 자리에서 다시 실패할 가능성이 높다. 이렇게 안내한다:

> 이건 양식으로 고칠 수 있는 오류가 아닙니다. **화면의 문구 전문**과 **세션 화면 주소**를
> 복사해서 개발팀에 전달해 주세요.

표에 없는 문구를 받았을 때도 같다. 지어내서 답하지 않는다.

## 3. 그래도 안 넘어갈 때

문구가 없는데 진행이 안 되는 경우다. 배지별로 본다.

### `이미지 대기` 에서 멈춤 — 가장 흔하고 가장 위험하다

파일 옆에 구체적인 실패 문구가 붙어 있다면 여기가 아니라 **§2.3(이미지 업로드 실패)을
먼저** 본다. 여기는 문구 없이 그냥 안 넘어가는 경우다.

**이 단계의 탈출로는 「세션 취소」뿐이다.** 「제외」는 `검토 가능` 이후에만 되므로 여기서는
쓸 수 없다. 취소하면 그 세션의 작업이 전부 날아간다. 그래서 이미지가 안 올라가는 원인을
정확히 가르는 것이 중요하다. 셋뿐이다.

**① 파일명이 다르다.** 화면의 **「올려야 하는 파일」** 목록에 있는 이름과 정확히 같은
파일이어야 한다. 비교는 **경로를 뗀 이름**으로, 대소문자와 앞뒤 공백을 무시하고 한다.
폴더 구조는 보지 않으므로 하위 폴더가 달라도 이름이 같으면 같은 파일 취급이다.
→ 목록의 이름 그대로 파일 이름을 바꾼 뒤 다시 올린다.

**② 포맷이나 용량이 안 맞는다.** 파일은 있는데 업로드가 실패한다. 자리마다 제약이 다르다:

| 쓰이는 자리 | 허용 포맷 | 최대 크기 |
|---|---|---|
| 대표이미지·부가이미지 | **jpg · png · webp 만** | **10MB** |
| 상세설명 본문 | 이미지 전부 | 20MB |

→ `.gif`·`.heic`·`.bmp` 를 대표이미지로 쓸 수 없다. jpg/png/webp 로 변환한 뒤, **파일명은
이미지 시트에 적힌 그대로 유지**해서 다시 올린다(확장자를 바꿔야 한다면 양식의 이미지
시트도 같이 고쳐 새 세션으로 올려야 한다).

**③ 요구 목록에 없는 파일만 올렸다.** 화면이 "요구 목록에 없어 건너뛴 파일 N건" 이라고
표시한다. 그 파일들은 올라가지 않는다.
→ 목록에 있는 파일을 올린다.

**요구 이미지가 1,000건을 넘으면 ③ 의 문구와 결론이 뒤집힌다.** 화면은 「올려야 하는
파일」 목록을 앞 1,000건까지만 불러오고, 매칭도 그 페이지 안에서만 벌어진다. 이때 이런
배너가 뜬다:

> 목록이 너무 커서 아래 …건만 불러왔습니다(전체 …건). 나머지는 이 화면에 보이지 않을 뿐
> 여전히 필요한 파일입니다 — 아래 목록에 없다고 해서 그 파일을 건너뛰어도 되는 것은
> 아닙니다.

같은 화면에서 안 올린 파일 목록의 제목도 `요구 목록에 없어 건너뛴 파일 N건` 이 아니라
**`요구 목록에서 확인하지 못한 파일 N건`**으로 바뀌고, 그 아래 "목록이 잘려 있어 이
파일들이 실제로 불필요한지 확인할 수 없습니다. 필요 없는 파일인지 다시 확인해 주세요."
가 덧붙는다. 이 배너가 보이면 ③ 의 결론(목록에 있는 파일만 올리면 된다)을 적용하지
않는다 — 워크북 이미지 시트에 적은 파일명을 그대로 믿고 전부 올린다. 상품 1,000행·
이미지 시트 상한을 감안하면 실제로 걸릴 수 있는 규모다.

일부만 실패했다면 **「실패한 것만 다시 시도」** 를 먼저 눌러 본다 — 일시적 실패였다면
그것으로 끝난다.

**확보하지 못한 이미지 때문에 멈췄다면 되돌릴 방법이 없다.** 취소하고, 이미지 시트에서
그 행을 빼고 새 세션으로 올린다. 이미지는 나중에 상품 상세 화면에서 붙인다. — 애초에
`SKILL.md` 절대 규칙 8 이 이 사고를 막으려는 것이다.

### `실패` 배지

슬라이스가 **10회 연속 실패**하면 이 상태로 확정된다. **재시도·재개로 풀리지 않는다.**
화면도 "이 상태는 재시도나 재개로 풀리지 않습니다" 라고 알려 준다. 「세션 취소」만 남는다.

취소한 뒤에는 원인을 모른 채 같은 파일을 다시 올리지 않는다 — 배너에 표시된 오류 문구를
§2 에서 찾아 원인을 먼저 가른다. 문구가 §2 에 없으면 §2.4 마지막 항목대로 에스컬레이션한다.

### `검토 가능` 인데 임시 버전이 없는 행

**고장이 아니다.** 행 옆에 이런 배지가 붙는다:

- `판매정책만 적용 (새 버전 없음)` — 조합 시트의 판매정책 4칸만 바뀐 행이다. 판매정책은
  상품 버전에 담기지 않고 발행 시점에 바로 적용되므로 새 버전을 만들 이유가 없다
- `변경 없음 (새 버전 없음)` — 실제로 바뀐 값이 하나도 없는 행이다

둘 다 정상이고, 발행하면 의도한 대로 반영된다.

### `검토 가능` 에서 재시도가 남기는 부작용

「draft 실패 행 재시도」는 **신규 상품 행에서 누를 때마다 내부 등록 기록이 한 번 더
쌓인다.** 원인을 확인하기 전에 반복해서 누르지 않는다. 실패 이유를 §2 에서 먼저 가른다.

### `취소됨` 이후 정리가 안 끝난다

「임시 데이터 정리」는 **한 번만 누르면 된다.** 버튼을 누르는 동안 화면이 안에서 API 를
반복 호출해(서버는 한 번에 100행씩 처리한다) 남은 수가 0 이 될 때까지 스스로 돈다 — 그동안
버튼은 비활성이고 진행 수치가 갱신된다. **다 돌고도 남은 수가 0 이 아니면** 더 이상 진전이
없다는 뜻이므로(영구 실패 행) 멈추고 개발팀에 알린다.

정리는 화면이 이렇게 알려 준다: `발행된 적 있는 행과 제외된 행은 건드리지 않습니다.` 수정
행은 임시 버전만, 신규 행은 상품까지 함께 지운다.

### 버튼을 눌렀는데 "다시 조회한 뒤 시도해 주세요"

`세션 상태가 그 사이 바뀌어 …하지 못했습니다. 다시 조회한 뒤 시도해 주세요.` 계열은
화면이 낡은 상태를 보고 있었다는 뜻이다. **새로고침하면 풀린다.** 다른 사람이 같은 세션을
동시에 조작했거나, 워커가 그 사이 단계를 넘겼을 때 난다.

### 「기다린다」 단계에서 몇 분째 안 넘어간다

`접수됨`·`검증 중`·`임시 버전 생성 중`·`발행 중` 은 백그라운드 작업이 도는 단계다.
새로고침해도 몇 분째 같은 배지이고 오류 배너도 없다면 스킬이 할 수 있는 일은 없다.
**세션 화면 주소와 배지 이름**을 들고 개발팀에 알린다.
