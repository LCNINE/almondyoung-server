# 멤버십 결제수단 수수료와 카드 재도입 근거

2026-10-20 조사. 월구독(4,990원)에 카드 결제를 다시 붙일지 판단하려고 실제 결제 기록으로 확인한 값이다.
블로그·시중 평균이 아니라 전부 우리 계약의 실측이다. 다시 확인할 때는 아래 「다시 뽑는 법」을 따른다.

## 한 건당 수수료 (부가세 포함)

| 결제 방식 | 4,990원 성공 | 실패 | 49,900원 | 근거 |
|---|---|---|---|---|
| 효성 카드 | 약 115원 (2.31%) | - | 약 1,153원 | Firebase 원장 `fee`=105(부가세 별도), 2023-10~2026-06 매달 2.10% 고정. 효성에 2.31%(=2.1%+부가세) 확인 |
| 토스 카드 | 161원 (공급가 146 + 부가세 15, 약 3.24%) | - | 1,619원 | 토스 정산 API, 2026-06~07 225건 |
| 효성 CMS (지금) | 275원 (`fee`=250) | 55원 (`fee`=50) | 275원 | wallet `cms_withdrawals.fee` 성공 476건 전부 250. 실패 90건은 효성 API 로 확인(전부 잔액부족 Q301) |
| 토스 가상계좌 | 330원 | - | 330원 | 토스 정산 API |

- 효성 API 의 `fee` 는 **부가세 별도**다. 카드 2.1% → 2.31%, CMS 250 → 275, 실패 50 → 55.
- 카드는 금액의 %, CMS 는 건당 정액이다. 그래서 **4,990원 월구독은 카드가 싸고, 49,900원 연간권은 CMS 가 싸다.**
- wallet 은 실패 출금의 수수료를 저장하지 않는다(`cms_withdrawals.fee` 가 성공 건에만 채워진다). 토스 수수료도 저장하지 않고, `payment_fee_rates` 도 비어 있다.

## 월구독 결제수단 변천

| 기간 | 방식 |
|---|---|
| 2023-09 ~ 2026-06 (카페24) | 효성 카드 정기결제 (토스 아님). CMS 는 2023-11 9건뿐 — 사실상 전부 카드. 월 결제 회원 830~960명(2026-05: 964명) |
| 2026-06-15 ~ 07-15 | 토스 카드 1회결제(30일권) |
| 2026-07-15 ~ 09-14 | 무통장(토스 가상계좌) 1회결제 |
| 2026-09-14 ~ | 효성 CMS 정기결제만 (`billing_path='INVOICE'`). 연간권은 계속 1회결제 |

## 전환·유지 지표 (2026-10-20 기준)

- 9/14 전후 4주: 신규 월 가입 주당 약 90 → 약 70 (-22%). 연간권은 주당 약 9 그대로.
- 1회 30일권은 만료 후 15일 안 재구매 18%(86/468).
- CMS 정기결제 2회차 결제 62% (첫 결제 35일 지난 114건 — 표본 작음).
- 카페24 효성 카드 정기결제 유지율 (2024-01 이후 첫 결제 코호트 약 2,700명): 2회차 70%, 3회차 57%, 4회차 51%, 7회차 41%.
  - 이탈자 약 19% 는 카드 결제 실패(거래정지·분실·유효기간 경과)로 끝났다.
  - 카드 실패 17만 건은 죽은 카드를 반복 재시도한 기록(회원·월당 평균 6.5회)이라 실패율 지표로 쓰면 안 된다.
- CMS 마찰: 약관 동의 후 가입 완료 89%(231/259명), 계좌 심사 실패 약 10%(주로 Q201 생년월일 불일치), 잔액부족 출금 실패 90건.
- 해지 사유에 결제수단 언급은 0건. 단, `cancellation_reasons` 선택지에 그 항목이 없다.
- 2026-05 카드 결제 회원 964명 vs 지금 자동결제가 켜진 CMS 계약 약 340건. 합계끼리 비교한 것이라 같은 사람이 옮겨 왔는지는 확인하지 않았다(개인정보 매핑 필요).

## 데이터 위치

- **카페24 시절 결제**: Firebase 프로젝트 `almond-auth` 의 `cardTransactions`(약 19.9만 건, 필드 `status`·`fee`·`callAmount`·`paymentDate`·`memberId`·`result.code`), `cmsTransactions`, `members`(`fmsMember.paymentKind`). 카페24 자체에는 결제 데이터가 없다 — 멤버십은 카페24 앱 AlmondAuth 가 처리했다.
- **지금 (membership DB)**: `subscription_contracts`(`billing_path`·`auto_renewal`·`recurring_cancellation_reason_code`), `subscription_contract_events`(CREATED `metadata.billingMode`, RECURRING_CANCELLED `metadata.reasonText`), `membership_terms_agreements`, `billing_events`.
- **지금 (wallet DB)**: `cms_members`, `cms_withdrawals`, `charges` + `payment_methods.type`. 멤버십 결제는 `payment_intents.metadata->>'type' = 'MEMBERSHIP_FEE'`. charge 행은 AUTHORIZE·CAPTURE 로 두 번 잡히니 건수를 셀 때 주의.

## 다시 뽑는 법

- 효성 출금 건별 수수료: `GET https://api.hyosungcms.co.kr/v1/payments/cms/{transactionId}`, 헤더 `Authorization: VAN {SwKey}:{CustKey}` (sst live secret). 응답 `payment.fee`.
- 토스 건별 수수료: `GET https://api.tosspayments.com/v1/settlements?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD&page=N&size=100`, Basic 인증(`TossSecretKey:`). `size=5000` 이나 `dateType` 을 넣으면 `INVALID_REQUEST` 가 난다. `fees[].fee` 합이 부가세 포함 수수료.
- 둘 다 GET 이라 상태를 바꾸지 않는다.

## 카드 정기결제 구현 상태

- wallet 에 토스·나이스페이 카드 빌링 provider 클래스(`providers/toss/toss-billing.provider.ts`, `providers/nicepay/nicepay-billing.provider.ts`)는 있지만 모듈에 등록돼 있지 않고 카드 등록 API 도 없다. 라이브 `billing_methods` 에 카드는 0건.
- 효성 신용카드 API 명세(FMS-TE-0040)가 업로드돼 있다. 효성과는 이미 CMS 로 연동돼 있어 효성 카드가 수수료로도 연동으로도 가장 가깝다.

## 법률 참고

금융위원회 2014-12-31 회신: 가맹점이 "일정한 거래에 대해 신용카드 거래를 허용하지 아니하는 것은 여신전문금융업법 제19조에 위반될 소지가 있다". 정기결제를 직접 다룬 해석은 아니므로 여신금융협회 확인이 필요하다.
